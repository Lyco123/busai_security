# 车辆专家拆分 A/B 测试方案

## 1. 背景与目标

- 当前车辆相关问题主要由 `omni` 统一处理，职责较宽，覆盖数据查询、分析解释、建议生成等多类任务。
- 车辆问题在语义上具备明显聚类特征，适合评估是否拆出专门的“车辆专家”以提升稳定性和专业性。
- 本方案只评估“是否拆分职责”这一个变量，不混入 CoT 开关，避免实验结论失真。

**核心问题**：
- 车辆相关问题从 `omni` 拆到“车辆专家”后，是否能提升回答质量、工具调用准确率和多轮稳定性？

## 2. 实验假设

- 假设 H1：拆出“车辆专家”后，车辆类问题的一次解决率、工具调用准确率和结构化输出稳定性提升。
- 假设 H0：拆分后收益不明显，或因路由成本和边界判断带来新的错误，整体收益不成立。

## 3. 实验范围

### 3.1 适用问题范围

- 车辆基础信息查询
- 车辆风险/故障/报警解释
- 车辆画像与车辆报告生成
- 车辆维保、维修、工单相关分析
- 车辆状态归因与整改建议

### 3.2 不纳入本次实验的范围

- 驾驶员、线路、单位等非车辆主体问题
- Router 规则匹配策略本身的 A/B 改造
- CoT 开关

## 4. 对照组设计

### 4.1 分组定义

- 方案 X：不拆分，车辆问题继续由 `omni` 直接处理
- 方案 Y：拆分，Router 识别车辆问题后转给“车辆专家”处理

### 4.2 单变量约束

- 两组都关闭 CoT
- 两组使用同一模型、同一温度、同一工具集权限边界
- 两组使用相同测试集、相同评估口径

### 4.3 盲测展示建议

- 前端继续沿用 `方案 X / 方案 Y` 的盲测文案
- 执行测试时不向测试人员暴露“X=omni / Y=车辆专家”的真实语义

## 5. 路由与职责定义

### 5.1 方案 X

- Router 命中车辆意图后，仍走现有 `omni` 链路
- `omni` 负责完成查询、分析、解释、建议生成

### 5.2 方案 Y

- Router 命中车辆意图后，优先转到“车辆专家”
- “车辆专家”仅负责车辆域问题
- 非车辆问题不得继续留在“车辆专家”内处理，应及时回退 Router 或转交其他链路

### 5.3 车辆专家的边界约束

- 只回答车辆主体相关问题
- 优先使用现有车辆相关工具和数据查询能力
- 不编造不存在的车辆信息
- 当用户问题切换到驾驶员、线路、单位等其他主体时，应退出当前专家链路

## 6. 评估指标

### 6.1 主指标

| 指标 | 说明 | 评估标准 |
|------|------|---------|
| 一次解决率 | 首轮或单次追问后是否完成用户目标 | 越高越好 |
| 工具调用准确率 | 是否调用了正确工具，参数是否合理 | 越高越好 |
| 回答专业性 | 是否围绕车辆主体，解释是否贴合车辆领域 | Eval 人审 |
| 多轮稳定性 | 多轮中主体不漂移、前后结论一致 | 越高越好 |
| 幻觉率 | 是否编造车辆数据、故障、工单等信息 | 越低越好 |

### 6.2 次指标

| 指标 | 说明 | 评估标准 |
|------|------|---------|
| 平均轮次 | 完成任务所需轮次 | 越低越好 |
| 平均耗时 | 单次请求端到端耗时 | 越低越好 |
| 用户满意度 | Eval 看板中的好/一般/差 | 越高越好 |
| 退出回退率 | 专家链路退出并回退到其他链路的比例 | 过高需排查 |

## 7. 测试场景与用例类型

| 用例 ID | 场景 | 对比重点 |
|---------|------|---------|
| VAB.1 | 车辆基础信息查询 | 是否更稳定地聚焦车辆主体 |
| VAB.2 | 车辆故障/报警解释 | 是否给出更专业、贴近车辆领域的解释 |
| VAB.3 | 车辆画像/报告生成 | 是否更完整、更少遗漏关键维度 |
| VAB.4 | 车辆维保/工单分析 | 是否能围绕维保语境组织回答 |
| VAB.5 | 车辆复杂多轮追问 | 是否保持上下文一致，不漂移到其他主体 |
| VAB.6 | 非车辆问题误入车辆链路 | 是否能正确回退，不越权回答 |

## 8. 执行流程

```text
1. 准备 30-50 条车辆类典型测试用例
   ->
2. 使用新建会话分别在方案 X / 方案 Y 下执行
   ->
3. 记录每轮 metadata、工具调用、耗时、最终结果
   ->
4. 在 Eval 看板中补充人工评分
   ->
5. 汇总统计主指标和次指标
   ->
6. 形成结论：是否拆分、拆分后适用边界、是否扩大到其他专家
```

## 11. 验收标准

- 车辆类测试集中，方案 Y 在主指标上优于方案 X
- 幻觉率不高于方案 X
- 专家退出回退率在可接受范围内
- 多轮稳定性明显优于方案 X
- 没有引入大规模误路由或新增越权回答

## 12. 风险与缓解

- 风险：车辆边界识别不准，导致误路由
- 缓解：先用显式车辆语义样本开展实验，边界样本单独统计

- 风险：拆分后回答变窄，复杂跨主体问题处理变差
- 缓解：要求“车辆专家”具备明确退出机制，复杂跨主体问题回退 Router

- 风险：测试员从回答风格猜出真实分组
- 缓解：沿用盲测标签 `方案 X / 方案 Y`，随机化执行顺序

## 13. 决策门槛

- 如果方案 Y 仅在个别子场景收益明显，则只对车辆报告/车辆分析等高价值场景启用
- 如果方案 Y 收益不稳定或带来较高误路由，则不推进专家拆分上线
