# Agent 路由 A/B 盲测重构方案

> 归档说明（2026-03-21）
>
> - 本方案对应的是 `force_rule` vs `router_decide` 的旧路由盲测方案。
> - 当前实验已切换为 [车辆专家拆分AB测试方案.md](./车辆专家拆分AB测试方案.md)。
> - 现网基线路由已固定为 `router_decide`，本文件仅作为历史留档，不再作为当前执行方案。

## 1. 背景与问题
- 现状 A/B 测试在前端直接暴露 `force_rule` / `router_decide`，存在明显测试者期望偏差。
- 测试方案强调阈值与路由细节，但对业务价值验证（结构化场景是否由 `rule_reply` 承担）不足。
- 统计指标可用，但“模式语义暴露 + 主观打分”导致结论可信度受损。

## 2. 重构目标
- 实现真正盲测：测试执行阶段不暴露真实策略语义。
- 保持系统可运营：后端仍按真实策略运行，前端仅做盲化展示和选择。
- 增加可追溯性：盲测映射有会话级持久化，保证同一会话内策略一致。
- 建立后续扩展位：后续可引入随机分配、交叉顺序、双盲复核。

## 3. 目标架构（重构后）
1. 前端展示层
- 不展示 `force_rule` / `router_decide` 文案。
- 统一展示为 `方案 X` / `方案 Y`（或策略组 1/2）。

2. 会话路由层
- 会话级生成随机映射：
- `X -> force_rule, Y -> router_decide` 或 `X -> router_decide, Y -> force_rule`。
- 映射持久化到浏览器 `localStorage`，确保同一会话不漂移。

3. 请求执行层
- 前端将盲化选择转换为真实 `abMode` 后发送。
- 后端无需改协议，继续消费 `abMode`。

4. 评估展示层
- 聚合统计面板仅显示“分组”而不显示策略语义。
- 研究/评估阶段只看行为结果与指标，不看模式名。

## 4. 分阶段实施计划
## Phase 1（已完成）
- 前端会话页引入盲测映射与盲化文案。
- A/B 按钮改为 `方案 X` / `方案 Y`。
- 会话锁定提示改为盲化标签，不再显示真实模式名。
- A/B 统计面板改为“策略组”展示，不暴露具体策略语义。

## Phase 2（建议 1-2 天内）
- 评估流程改造：
- 固化测试顺序随机化（同一用例随机先跑 X 或 Y）。
- 增加“不可查看 metadata 原始 mode”限制（测试角色维度）。
- 记录每条评测的顺序位次与轮次号，便于消除顺序效应。

## Phase 3（建议 1 周内）
- 指标体系升级：
- 新增认知成本指标（追问次数、改写次数、会话中断率、完成时长）。
- 新增业务价值指标（结构化查询命中 `rule_reply` 的覆盖率、一次解决率）。
- 新增偏差监控（同测试员对不同组的评分漂移）。

## 5. 验收标准
- 测试执行页面不出现 `force_rule` / `router_decide` 文案。
- 同一会话内盲测方案稳定不变，刷新页面后仍一致。
- 后端请求仍能正确接收并执行真实 `abMode`。
- 统计看板可对比两组数据，但无法从页面文本直接判断真实策略。

## 6. 风险与缓解
- 风险：测试员可通过行为“猜模式”。
- 缓解：扩大样本量、随机化顺序、跨测试员复核。

- 风险：旧会话历史已锁定真实策略，语义可能不一致。
- 缓解：旧会话标记为“历史锁定（非盲测会话）”，不纳入盲测主样本。
