# 车辆专家 CoT 开关 A/B 测试方案

## 1. 背景与目标

- 计划中的“车辆专家”会承担更强的车辆分析、归因和报告生成职责。
- CoT 可能提升复杂推理质量，但也可能带来更高时延和成本，并影响工具调用稳定性。
- 本方案只评估“车辆专家是否开启 CoT”这一个变量，不混入是否拆分专家的因素。

**核心问题**：
- 在“车辆专家”已经存在的前提下，开启 CoT 是否能为车辆复杂任务带来稳定收益？

## 2. 实验假设

- 假设 H1：在车辆专家链路中开启 CoT 后，复杂分析、归因解释、报告生成的质量提升。
- 假设 H0：开启 CoT 的收益不足以覆盖时延、成本和工具调用不稳定带来的代价。

## 3. 实验前提

- 车辆专家已经从 `omni` 中拆出，并能稳定接收车辆域请求
- 实验期间，Router 与车辆专家职责不变
- 只调整 CoT 开关，不调整 prompt、工具权限和路由规则

## 4. 对照组设计

### 4.1 分组定义

- 方案 X：车辆专家关闭 CoT
- 方案 Y：车辆专家开启 CoT

### 4.2 单变量约束

- 两组使用同一车辆专家 prompt
- 两组使用同一模型版本
- 两组使用同一工具集和同一超参数，除 CoT 开关外不做其他改动

### 4.3 适用范围

- 本实验仅对“车辆专家”生效
- `omni`、Router、轻量查询链路默认不参与本实验

## 5. 重点评估场景

| 用例 ID | 场景 | 预期 CoT 收益点 |
|---------|------|----------------|
| VCOT.1 | 车辆故障归因 | 多因素归因更完整 |
| VCOT.2 | 车辆多指标风险解释 | 证据组织更清晰 |
| VCOT.3 | 车辆报告生成 | 结构完整度更高 |
| VCOT.4 | 车辆维保整改建议 | 推理链条更连贯 |
| VCOT.5 | 复杂多轮追问 | 上下文一致性更强 |
| VCOT.6 | 简单查询场景 | 验证 CoT 是否造成过度推理和无谓成本 |

## 6. 评估指标

### 6.1 主指标

| 指标 | 说明 | 评估标准 |
|------|------|---------|
| 复杂任务完成率 | 对复杂分析、归因、报告任务是否完成目标 | 越高越好 |
| 推理质量 | 结论是否有证据支撑，逻辑是否完整 | Eval 人审 |
| 工具调用正确率 | CoT 下是否仍保持稳定的工具选择与参数质量 | 越高越好 |
| 结构化输出合法率 | 报告/JSON 输出是否满足约束 | 越高越好 |
| 幻觉率 | 是否凭空补充未查询到的车辆事实 | 越低越好 |

### 6.2 成本与性能指标

| 指标 | 说明 | 评估标准 |
|------|------|---------|
| 平均耗时 | 端到端响应时间 | 越低越好 |
| 输入输出 token | 重点关注输出增长 | 越低越好 |
| 平均轮次 | 是否减少反复追问 | 越低越好 |
| 单任务成本 | 估算 token 成本 | 越低越好 |

## 7. 实验样本设计

### 7.1 样本数量建议

- 复杂车辆任务：20-30 条
- 简单车辆查询：10-20 条
- 总样本：30-50 条

### 7.2 样本分层

- 查询型
- 解释型
- 归因型
- 报告型
- 多轮型

## 8. 执行流程

```text
1. 固定车辆专家版本与测试集
   ->
2. 对每条测试用例分别跑方案 X / 方案 Y
   ->
3. 记录工具调用、耗时、token、最终结果与人工评分
   ->
4. 按“复杂任务”和“简单任务”分别汇总
   ->
5. 判断 CoT 是否只在复杂任务中有收益
   ->
6. 决策是否仅对复杂车辆任务开启 CoT
```

## 11. 验收标准

- 在复杂车辆任务上，方案 Y 的完成率、推理质量、结构化输出合法率至少两项明显优于方案 X
- 简单查询场景中，方案 Y 不应明显拉高时延和成本
- 工具调用正确率不能因 CoT 明显下降
- 幻觉率不能升高

## 12. 风险与缓解

- 风险：CoT 拉高时延，影响交互体验
- 缓解：将简单查询与复杂分析分层统计，避免平均值掩盖问题

- 风险：CoT 导致模型过度推理，回答变长但价值不高
- 缓解：将“回答有效信息密度”纳入人工评审

- 风险：切换到新模型后结果不可比
- 缓解：先在当前模型内完成 CoT 开关实验，再对目标模型单独复测

## 13. 决策门槛

- 如果 CoT 只在复杂任务中有明确收益，则仅对车辆专家的复杂分析/报告链路开启
- 如果 CoT 在简单查询场景中收益不明显且成本上升，则简单查询保持关闭
- 如果 CoT 带来稳定的工具调用退化或显著成本上升，则暂不上线

## 14. 推荐上线策略

- 默认策略：不为所有 agent 开 CoT
- 优先策略：仅为“车辆专家”的复杂任务链路灰度开启
- 后续扩展：若车辆专家验证收益明确，再复制到驾驶员专家、线路专家等高复杂度专家链路
