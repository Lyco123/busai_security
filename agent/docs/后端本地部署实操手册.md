# 后端本地部署实操手册 (Docker版)

这份文档是专门为**不熟悉 Docker 的开发者**准备的。我们将一步步指引你如何将 Agent 后端服务打包并在本地服务器上运行。

## 0. 核心概念：为什么用 Docker？

你可以把 Docker 想象成一个 **"标准化的集装箱"**。
*   **以前**：你需要在服务器上安装 Node.js、安装 PostgreSQL、配置环境变量、处理各种版本冲突。
*   **现在**：我们把代码、运行环境、数据库配置全部打包进这个“集装箱”里。无论你把这个箱子搬到哪台服务器上，只要服务器装了 Docker，箱子里的东西就能原样运行，**彻底告别 "在我电脑上能跑，在服务器上跑不起来" 的问题**。

## 1. 环境准备

### 1.1 安装 Docker
*   **Windows (开发测试用)**: 下载并安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)。安装后启动它，看到鲸鱼图标即成功。
*   **Linux 服务器 (部署用)**: 在终端运行以下命令一键安装：
    ```bash
    curl -fsSL https://get.docker.com | bash
    ```

### 1.2 验证安装
打开终端（CMD 或 PowerShell），输入：
```bash
docker --version
docker-compose --version
```
如果能看到版本号，说明环境已就绪。

## 2. 配置文件准备 (Copy & Paste)

我们需要在项目根目录（`agent/` 文件夹下）创建三个关键文件。

### 文件 1: `Dockerfile`
**作用**：告诉 Docker 如何把你的代码“打包”成一个镜像。

在 `agent/` 下新建 `Dockerfile` (无后缀名)，填入以下内容：

```dockerfile
# 1. 选择基础镜像：使用轻量级的 Node.js 20
FROM node:20-alpine

# 2. 设置工作目录
WORKDIR /app

# 3. 安装依赖 (利用缓存机制，先拷 package.json)
COPY package.json package-lock.json ./
RUN npm ci --production

# 4. 复制所有源代码
COPY . .

# 5. 暴露端口 (告诉 Docker 这个程序用 3000 端口)
EXPOSE 3000

# 6. 启动命令 (运行编译后的 Node.js 入口)
# 注意：这里假设你有一个专门适配 Node 的入口文件
CMD ["node", "dist/index.node.js"]
```

### 文件 2: `.dockerignore`
**作用**：告诉 Docker 打包时忽略哪些垃圾文件（类似 `.gitignore`）。

在 `agent/` 下新建 `.dockerignore`，填入：

```text
node_modules
dist
.git
.env
*.log
```

### 文件 3: `docker-compose.yml`
**作用**：这是**最重要的指挥官**。它告诉 Docker 同时启动后端、数据库和 Redis，并把它们自动连起来。

在 `agent/` 下新建 `docker-compose.yml`，填入：

```yaml
version: '3.8'

services:
  # --- 服务 1: 我们的 Agent 后端 ---
  backend:
    build: .              # 使用当前目录的 Dockerfile 构建
    container_name: agent-backend
    restart: always       # 崩溃或重启服务器后自动启动
    ports:
      - "3000:3000"       # 左边是服务器端口，右边是容器端口
    environment:
      - NODE_ENV=production
      - DATABASE_URL=postgresql://postgres:mysecretpassword@db:5432/agent_db
      - REDIS_URL=redis://redis:6379
      # 如果要连宿主机的 vLLM，请用 host.docker.internal
      - LLM_API_BASE=http://host.docker.internal:8000/v1
    depends_on:
      - db
      - redis

  # --- 服务 2: 数据库 (PostgreSQL) ---
  db:
    image: postgres:15-alpine
    container_name: agent-db
    restart: always
    environment:
      - POSTGRES_USER=postgres
      - POSTGRES_PASSWORD=mysecretpassword
      - POSTGRES_DB=agent_db
    volumes:
      - ./pgdata:/var/lib/postgresql/data  # 把数据存在当前目录的 pgdata 文件夹，防止丢失

  # --- 服务 3: 缓存 (Redis) ---
  redis:
    image: redis:alpine
    container_name: agent-redis
    restart: always

# 自动创建网络让它们互通
networks:
  default:
    name: agent-network
```

## 3. 代码适配 (关键一步)

由于 Cloudflare Workers 和 Docker (Node.js) 的运行原理不同，你需要一个专门的 **Node.js 入口文件**。

假设你使用 Hono 框架，请在 `src/` 下新建 `index.node.ts`：

```typescript
import { serve } from '@hono/node-server'
import { Hono } from 'hono'
import { app } from './index' // 引入你原本的 app 逻辑

// 创建一个新的 Hono 实例或者直接使用原本的 app
// 关键是使用 @hono/node-server 来运行它
const port = 3000
console.log(`Server is running on port ${port}`)

serve({
  fetch: app.fetch,
  port
})
```

*记得在 `package.json` 的 `scripts` 里加一个 build 命令，把 ts 编译成 js，例如 `tsc`。*

## 4. 启动与操作 (傻瓜式命令)

打开终端，进入 `agent/` 目录。

### 场景 A: 第一次启动 / 修改了代码后
当你写完代码，或者刚把代码拉到服务器上时，执行这三步：

1.  **打包镜像** (把代码封进集装箱):
    ```bash
    docker-compose build
    ```
2.  **启动服务** (后台运行):
    ```bash
    docker-compose up -d
    ```
    *( `-d` 表示 Detached，即在后台静默运行，不会卡住你的终端)*
3.  **查看状态**:
    ```bash
    docker-compose ps
    ```
    *如果你看到所有服务的 State 都是 `Up`，恭喜你，部署成功了！*

### 场景 B: 查看日志 (Debug)
如果程序跑不通，或者想看输出日志：

```bash
# 查看后端的实时日志
docker-compose logs -f backend

# 查看数据库日志
docker-compose logs -f db
```
*(按 `Ctrl + C` 退出日志查看)*

### 场景 C: 停止服务
```bash
docker-compose down
```

## 5. 常见问题 FAQ

**Q: 数据库的数据存在哪？删了容器数据会丢吗？**
A: 不会。在 `docker-compose.yml` 里我们配置了 `volumes: ./pgdata:...`。这意味着数据库文件实际存储在你的 `agent/pgdata` 文件夹里。只要你不手动删这个文件夹，重启或删除容器数据都在。

**Q: `host.docker.internal` 是什么？**
A: 这是一个特殊的域名，允许 Docker 容器内部访问**宿主机**（也就是你的服务器/电脑）的端口。因为 vLLM 是直接跑在显卡服务器上的（没在 Docker 里），所以后端需要通过这个域名“跳”出容器去访问 vLLM。

**Q: 端口被占用了怎么办？**
A: 修改 `docker-compose.yml` 里的 `ports`。例如 `8080:3000` 表示把服务器的 8080 映射到容器的 3000。
