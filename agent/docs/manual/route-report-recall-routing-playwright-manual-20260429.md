# 线路报告生成召回率与路由 Playwright 手动测试手册（4/29 批次）

日期：2026-04-29  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送用户消息  
测试目标：专项检验线路报告生成管线的**召回率**（应进入线路报告生成相关流程）、**不误召**（不应进入该管线）、**澄清行为**是否合理、以及长等待下的**系统稳定性**。本批次与 4/23 不同：**用户只提线路名称，不提日期/分区，考察系统能否仅凭对象名完成路由与数据定位**。

样例数据来源：`agent/docs/mcp-usable-samples-20260410.md`（与 demo `fixtures` 一致）。

---

## 1. 测试范围（本轮不覆盖）

- 标准、规范的「请生成线路安全风险分析总结报告 + 线路名 + 分区」等**正常表述含分区**已在其他轮次验证，**本轮不测**。
- 本轮聚焦：**仅用线路名（不提日期分区）/ 近义词 / 口语 / 中英混排 / 参数分散与澄清 / 易混意图**。

---

## 2. 数据约束（唯一允许）

仅允许使用以下线路数据（勿改线路名）：

```json
{ "routeName": "527" }
```

与车辆样例交叉对照时，仅可使用同文档中的车牌（用于**不应进入线路报告**的负例）：`粤A02650D`、`粤A02013D`。

**本轮不提分区 `ppartition`**，用户输入中仅用线路名指代对象。

## 4. 判定口径

### 4.1 权威判定依据：`metadata.tool`

**是否召回本管线**，以助手回复（或消息落库）中的 **`metadata.tool`** 为准，例如：

```json
"metadata": {
  "tool": "generate_route_report"
}
```

未路由到具体工具时，`tool` 可能为 **空字符串 `""`**、缺省或其它工具名，以实际返回为准。

| 场景               | 对 `metadata.tool` 的要求                  |
| ------------------ | ------------------------------------------ |
| **应召回（R+）**   | 必须等于 **`generate_route_report`**。     |
| **不应召回（R−）** | **不得**等于 **`generate_route_report`**。 |

若页面「执行 Agent」与 `metadata.tool` 不一致，**以 `metadata.tool` 为判定依据**，并在备注中说明。

### 4.2 业务意图（与 §4.1 对照理解）

- **应召回（R+）**：用户真实意图为「指定线路的正式线路安全/管理向总结类报告」，且能落到 `routeName = 527` 时，应进入线路报告生成管线（含：先合理澄清缺参再进入）。本轮用户**不提日期分区**，系统需仅凭线路名完成路由；若系统需分区参数，允许澄清追问。
- **不应召回（R−）**：意图为**车辆**报告、仅属性查询、明确拒绝报告、多线路对比/泛咨询等，**不得**进入线路报告生成管线；acceptable 为澄清、`consult_omni`、基础查询、或进入 `generate_vehicle_report`（当用户明确要车时）等。

## 5. 十轮用例设计

### 5.1 应召回（5 例）— 仅线路名、不提日期

| 轮次 | ID  | 考察点                             | 用户输入（可复制）                                                                                            |
| :--: | :-- | :--------------------------------- | :------------------------------------------------------------------------------------------------------------ |
|  1   | R+1 | 「报告」的近义：调度管理、风险汇总 | **527路**，调度管理要看**安全风险汇总**，管理人员版。                                                         |
|  2   | R+2 | 口语化「搞一份输出」               | **搞一份** **527路** **安全方面**的正式输出，别给碎片化问答。                                                 |
|  3   | R+3 | 「527路」带路字、正式版            | **527路** 的**线路安全总结报告**。                                                                            |
|  4   | R+4 | **澄清**：首轮缺参，次轮补线路名   | **Q1：** 我要**线路级**的安全总结，模块别缺。 **（等待回复后再发 Q2，仍在本会话）** **Q2：** 线路 **527路**。 |
|  5   | R+5 | 中英混排、ops 表述                 | **Ops safety summary (management)** for **route 527**.                                                        |

**R+ 预期摘要：** 最终 `metadata.tool` 应为 **`generate_route_report`**；R+4 允许第一轮仅澄清，第二轮补参后应命中该工具。

### 5.2 不应召回（5 例）— 易混意图、否定、多线路、无线路主体

| 轮次 | ID  | 考察点                                    | 用户输入（可复制）                                                          |
| :--: | :-- | :---------------------------------------- | :-------------------------------------------------------------------------- |
|  6   | R−1 | 易混：**车辆**安全报告 vs 线路报告        | 我要**车辆**安全报告，车牌 **粤A02013D**，**别提线路编号**。                |
|  7   | R−2 | 明确不要「报告」，点状运营信息            | **别出正式报告**，只要 **527路** 的**配车数、首末班**这类**运营点点信息**。 |
|  8   | R−3 | 仅确认数据是否存在（非报告）              | **不要生成报告**。请确认 **527路** **有没有线路画像数据**就行。             |
|  9   | R−4 | 两条线路对比/概况（非单线路长篇报告管线） | **527** 和 **100130** **对比概况**，**不要只给一条线的长篇正式报告**。      |
|  10  | R−5 | 无具体线路、泛问题（测不误召与稳定性）    | 公交线路客流高峰安全风险一般怎么谈？**先不说具体哪条线路。**                |

**R− 预期摘要：** `metadata.tool` **不得**为 **`generate_route_report`**；可出现澄清、车辆报告、其他 Agent、或通用问答。
