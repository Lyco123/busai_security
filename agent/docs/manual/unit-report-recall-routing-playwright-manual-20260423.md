# 单位报告生成召回率与路由 Playwright 手动测试手册（4/23 批次）

日期：2026-04-23  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送（不推荐本仓库内自动化脚本批量跑，便于观察每轮回复与页面状态）  
测试目标：检验单位报告生成管线的路由召回——在用户意图为「要单位/组织管理人员版安全总结类报告」时，是否稳定进入 `generate_unit_report` 对应链路；在不应进入该管线时，是否表现为澄清、咨询（`consult_omni` 等）或进入驾驶员等其他合理管线，而非误生成单位报告。本批次话术与 4/12 轮次不同，用于回归多轮承接与负例稳定性。

样例约束与 `agent/docs/mcp-usable-samples-20260408.md` / `agent/docs/mcp-usable-samples-20260410.md` 中约定一致。

## 1. 测试范围与目标

本设计聚焦**边缘**与**多轮**（不包含「正常一次性给全参数且成功出报告」的重复验证）。记录时以业务可观察行为为主。

## 2. 数据约束（仅此两组）

**单位（单位报告正向用例必须使用）**

```json
{
  "organName": "二巴公司",
  "ppartition": "20251221"
}
```

**驾驶员（仅用于「应不进入单位报告」或「多轮需求切换」对照，不得编造第三名驾驶员或其他分区）**

```json
{
  "driverName": "任宇邦",
  "ppartition": "20251221"
}
```

**禁止**在测试中引入其他单位全称、其他分区或其他业务主键，避免干扰「路由」结论。

## 4. 判定口径（召回 / 路由）

### 4.1 权威判定依据：`metadata.tool`

**是否召回单位报告管线**，以助手回复（或消息落库）中的 **`metadata.tool`** 为准，例如：

```json
"metadata": {
  "tool": "generate_unit_report"
}
```

未路由到具体工具时，`tool` 可能为 **空字符串 `""`**、缺省或其它工具名（如 `consult_omni`、`generate_driver_report`），以实际返回为准。

| 场景                       | 对 `metadata.tool` 的要求                 |
| -------------------------- | ----------------------------------------- |
| **R+（应进入单位报告）**   | 必须等于 **`generate_unit_report`**。     |
| **R−（不应进入单位报告）** | **不得**等于 **`generate_unit_report`**。 |

若页面「执行 Agent」与 `metadata.tool` 不一致，**以 `metadata.tool` 为判定依据**，并在备注中说明。

### 4.2 业务意图（与 §4.1 对照理解）

- **R+（单位报告应召回且正确）**：用户明确要**单位**（管理人员版安全总结 / 单位画像正式报告等）且目标单位可唯一落到「二巴公司」+ 分区 `20251221`（或系统等价理解），并进入单位报告生成流程（或合理澄清后进入）。
- **R−（单位报告应不召回）**：用户意图为**驾驶员个人报告**、仅咨询不生成报告、缺单位名、歧义多目标等，系统**不应**在信息不足或意图不符时强行生成「二巴公司」单位完整报告；acceptable 行为包括：澄清问句、走 `consult_omni`、或进入 `generate_driver_report`（当用户要的是任宇邦时）。
- **误路由（单位报告维度）**：在 R− 场景下 **`metadata.tool` 仍为 `generate_unit_report`**；或在 R+ 场景下应命中却未命中（`metadata.tool` ≠ `generate_unit_report`），或 R+ 场景下在无用户要驾驶员的表述时错误地为 `generate_driver_report` 且始终未进入单位报告（按产品定义记入备注）。

## 6. 边缘用例（E1–E5）

### E1 — 应召回单位报告（R+）

- **新建会话**
- **用户输入：**

```text
请输出二巴公司在数据分区 20251221 下的单位安全风险分析总结（管理人员版）正式报告。
```

- **预期**：识别为单位报告生成需求，针对「二巴公司」与分区 `20251221` 进入 `generate_unit_report` 管线（或极短确认后进入）；不应误走成任宇邦驾驶员报告。

### E2 — 应召回单位报告（R+）

- **新建会话**
- **用户输入：**

```text
我要做组织维度的安全管理复盘，单位就二巴公司这一家，分区只要 20251221 对应的完整单位报告，不要个人驾驶员版。
```

- **预期**：「组织维度」「不要个人版」应强化单位管线；单位唯一（二巴公司）、分区明确；稳定路由至单位报告生成。

### E3 — 应不召回单位报告（R−，意图类型为驾驶员）

- **新建会话**
- **用户输入：**

```text
给我驾驶员任宇邦在 20251221 分区的个人安全分析报告，要司机单人版，不要单位汇总。
```

- **预期**：应走向**驾驶员报告**（`generate_driver_report`），**不应**生成二巴公司单位报告。

### E4 — 应不召回单位报告（R−，缺参）

- **新建会话**
- **用户输入：**

```text
20251221 这个分区，帮我出一份单位侧的安全风险分析总结报告，管理人员版。（先不说是哪家单位）
```

- **预期**：缺少具体单位名称，应追问「哪个单位」等，**不得**在无确认时默认填「二巴公司」并直接生成单位报告。

### E5 — 应不召回单位报告（R−，咨询非生成）

- **新建会话**
- **用户输入：**

```text
二巴公司在 20251221 分区整体风险先给结论，再列三条要点解读就行；不要生成完整正式报告，也不要报告排版格式。
```

- **预期**：适合 `consult_omni` 类解读；**不应**调用 `generate_unit_report` 输出完整 JSON 报告。

## 7. 多轮对话用例（M1–M5）

每例：**同一会话**内按顺序发送；**每一步发送后等待约 2 分钟**。

### M1 — 需求变更（无关 → 单位报告）

| 步骤 | 用户输入                                                                                         |
| :--: | :----------------------------------------------------------------------------------------------- |
|  1   | `上海外滩今天拥挤吗？`                                                                           |
|  2   | `不说这个了。请按业务数据生成二巴公司在分区 20251221 的单位安全风险分析总结报告（管理人员版）。` |

- **预期**：第 1 步可拒答或简短说明范围；第 2 步应**切换**到单位报告意图，路由至 `generate_unit_report`，不因第 1 步污染。

### M2 — 信息分散（先单位名后分区）

| 步骤 | 用户输入                                       |
| :--: | :--------------------------------------------- |
|  1   | `二巴公司的管理人员安全总结我这边要立项用。`   |
|  2   | `刚漏了分区：20251221，请按正式报告流程输出。` |

- **预期**：第 2 步视为补参，最终应对「二巴公司 + 20251221」进入单位报告生成；中间不应因顺序导致退成纯咨询且无报告（除非产品明确如此）。

### M3 — 信息分散（先分区后单位名）

| 步骤 | 用户输入                                                         |
| :--: | :--------------------------------------------------------------- |
|  1   | `20251221 分区能选哪些组织级的安全类产出？先列类型。`            |
|  2   | `那就给二巴公司出这个分区下的单位安全风险分析总结，管理人员版。` |

- **预期**：第 2 步锁定「二巴公司 + 20251221」，进入单位报告管线；第 1 步若为列举能力，第 2 步应能承接单位名。

### M4 — 追加解释（首轮模糊）

| 步骤 | 用户输入                                                                  |
| :--: | :------------------------------------------------------------------------ |
|  1   | `帮我做个公司层面安全材料，管理要看。`                                    |
|  2   | `补充：要单位正式安全风险分析总结报告，主体二巴公司，数据分区 20251221。` |

- **预期**：第 2 步消除歧义并进入 `generate_unit_report`；第 1 步允许追问，但若第 2 步已给全信息则不应无谓拖延。

### M5 — 纠错（错误分区 → 正确分区）

| 步骤 | 用户输入                                                                |
| :--: | :---------------------------------------------------------------------- |
|  1   | `生成二巴公司的单位安全风险分析总结报告（管理人员版），分区 20251101。` |
|  2   | `分区写错了，应该是 20251221，请按这个分区继续单位报告。`               |

- **预期**：第 2 步以纠正后的分区为准继续单位报告流程；若第 1 步因数据问题失败，第 2 步应能恢复并成功路由到单位报告。
