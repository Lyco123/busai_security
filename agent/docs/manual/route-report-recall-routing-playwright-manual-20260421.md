# 线路报告生成召回率与路由 Playwright 手动测试手册

日期：2026-04-21  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送用户消息  
测试目标：在**正常路径已验证通过**的前提下，专项检验线路报告生成管线的**召回率**（应进入线路报告生成相关流程）、**不误召**（不应进入该管线）、**澄清行为**是否合理、以及长等待下的**系统稳定性**。

样例数据来源：`agent/docs/mcp-usable-samples-20260410.md`（与 demo `fixtures` 一致）。

---

## 1. 测试范围（本轮不覆盖）

- 标准、规范的「请生成线路安全风险分析总结报告 + 线路名 + 分区」等**正常表述**已在其他轮次验证，**本轮不测**。
- 本轮聚焦：**近义词 / 口语 / 不规范写法 / 中英混排 / 参数分散与澄清 / 易混意图**。

---

## 2. 数据约束（唯一允许）

仅允许使用以下线路数据（线路名与分区一一对应，勿改数字）：

```json
{ "routeName": "527", "ppartition": "20251221" }
```

与车辆样例交叉对照时，仅可使用同文档中的车牌（用于**不应进入线路报告**的负例）：`粤A02650D`、`粤A02013D`，分区仍为 `20251221`。

---

## 3. 执行规范

| 项   | 要求                                                                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话 | **每一轮（R+1～R−5）单独新建会话**，避免上文干扰路由判定。                                                                                      |
| 等待 | 每发送**一条**用户消息后，**等待约 2 分钟**再读取助手回复（大模型较慢）；若界面出现「生成中」等中间态，可在最终文案出现后再补等数十秒确认落点。 |
| 记录 | 建议同时记录页面展示的 **执行 Agent / 工具名**（若可见）、是否出现错误页/超时/重试。                                                            |

---

## 4. 判定口径

- **应召回（R+）**：用户真实意图为「指定线路的正式线路安全/管理向总结类报告」，且能落到 `routeName = 527, ppartition = 20251221` 时，应进入线路报告生成管线（含：先合理澄清缺参再进入）。
- **不应召回（R−）**：意图为**车辆**报告、仅属性查询、明确拒绝报告、多线路对比/泛咨询等，**不得**进入线路报告生成管线；acceptable 为澄清、`consult_omni`、基础查询、或进入 `generate_vehicle_report`（当用户明确要车时）等。

## 5. 十轮用例设计

### 5.1 应召回（5 例）— 近义词、口语、不规范表达、澄清后续跑通

| 轮次 | ID  | 考察点                               | 用户输入（可复制）                                                                                                                                   |
| :--: | :-- | :----------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------- |
|  1   | R+1 | 「报告」的近义：总结 / 管理视角      | **527路** 这条线路我要一份**安全风险分析总结**，管理口看的，画像日期 **20251221**。                                                                  |
|  2   | R+2 | 口语化、省略「生成」                 | **帮我整一下** **527** **那条线路**的安全方面材料，就 **20251221** 那天档期的。                                                                      |
|  3   | R+3 | 不规范：空格、标点、日期口语         | 线路 **5 27**（中间有空格），要看**线路安全总结报告**，时间：**2025年12月21号** 的画像（若系统只认 yyyyMMdd，看是否澄清或等价映射到 **20251221**）。 |
|  4   | R+4 | **澄清**：首轮缺参，次轮补全两组字段 | **Q1：** 我想看**线路管理人员版**那种安全总结，你帮我把版式出全。 **（等待回复后再发 Q2，仍在本会话）** **Q2：** 线路是 **527**，分区 **20251221**。 |
|  5   | R+5 | 中英混排、partition 英文             | Please give me the **route safety summary (management)** for **527**, **ppartition=20251221**.                                                       |

**R+ 预期摘要：** 最终应走到线路报告生成相关能力；R+4 允许第一轮仅澄清，第二轮补参后应进入管线。

### 5.2 不应召回（5 例）— 易混意图、否定、多线路、无线路主体

| 轮次 | ID  | 考察点                                                       | 用户输入（可复制）                                                                              |
| :--: | :-- | :----------------------------------------------------------- | :---------------------------------------------------------------------------------------------- |
|  6   | R−1 | 易混：**车辆**安全报告 vs 线路报告（同分区，车牌为样例数据） | 我要 **车辆**安全风险分析报告，车那侧的，车牌 **粤A02650D**，日期 **20251221**（别提线路名）。  |
|  7   | R−2 | 明确不要「报告」，只要属性/档案感                            | **别出正式报告**，我就问下 **527路** 在 **20251221** 的线路类型、所属车队这些**基础档案**。     |
|  8   | R−3 | 仅确认数据是否存在（非报告）                                 | **不要生成报告**。请确认 **527路** 在 **20251221** 分区**有没有线路画像数据**就行。             |
|  9   | R−4 | 两条线路对比/概况（非单线路长篇报告管线）                    | **对比** **527** 和 **100130** 在 **20251221** 的**基本情况**，不要只给一条线路的长篇正式报告。 |

**R− 预期摘要：** 不应进入线路报告生成管线；可出现澄清、车辆报告、其他 Agent、或通用问答，但不应产出与「单线路正式安全总结报告」同级的误触发。

## 9. 用例设计依据

本 manual 依据当前线路报告管线的路由规则设计，参考：

- 驾驶员报告召回手册 `agent/docs/manual/driver-report-recall-routing-playwright-manual-20260418.md`
- 车辆报告召回手册 `agent/docs/manual/vehicle-report-recall-routing-playwright-manual-20260414.md`
- 综合路由复测 `agent/docs/manual/report-routing-playwright-manual-rerun-20260418.md`

历史结论：线路报告管线在 4/16 ~ 4/18 所有测试中召回率为 **0%**，始终表现为 `tool=null` 或 `consult_omni`，线路报告管线路由层尚未稳定接入。

**本轮（4/21）结论**：线路报告管线召回率已恢复到 **100%**（5/5应召回+5/5不应召回全部通过），`generate_route_report` 管线路由已修通。
