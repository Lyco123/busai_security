# 单位报告路由召回率 Playwright 手动测试记录

日期：2026-04-12  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：Playwright 手动逐条发送（不推荐本仓库内自动化脚本批量跑，便于观察每轮回复与页面状态）  
测试目标：检验单位报告生成管线的路由召回率——在用户意图为「要单位/组织管理人员版安全总结类报告」时，是否稳定进入 `generate_unit_report` 对应链路；在不应进入该管线时，是否表现为澄清、咨询（`consult_omni` 等）或进入驾驶员等其他合理管线，而非误生成单位报告。

## 1. 测试范围与目标

本设计聚焦**边缘**与**多轮**（不包含「正常一次性给全参数且成功出报告」的重复验证）。记录时以业务可观察行为为主。

## 2. 数据约束（仅此两组）

以下 JSON 与 `agent/docs/mcp-usable-samples-20260408.md` 约定一致；对话中可用自然语言表述同一含义（单位名、驾驶员姓名、分区日期）。

**单位（单位报告正向用例必须使用）**

```json
{
  "organName": "二巴公司",
  "ppartition": "20251221"
}
```

**驾驶员（仅用于「应不进入单位报告」或「多轮需求切换」对照，不得编造第三名驾驶员或其他分区）**

```json
{
  "driverName": "任宇邦",
  "ppartition": "20251221"
}
```

**禁止**在测试中引入其他单位全称、其他分区或其他业务主键，避免干扰「路由」结论。

## 3. 执行规范

| 项 | 要求 |
|---|---|
| 会话 | **单轮边缘用例（E1–E5）**：每个用例**新建会话**。**多轮用例（M1–M5）**：全程**同一会话**内按步骤发送。 |
| 等待 | 每发送一条用户消息后 **等待约 2 分钟** 再读取助手回复；若出现「生成中」类状态，可再补等约 30–60 秒确认落点。 |
| 记录 | 建议截图或复制：用户输入、助手最终回复、若页面展示「执行 Agent / 工具名」则一并记下。 |
| 范围 | **不包含**「正常一次性给全参数且成功出单位报告」的重复验证；本设计聚焦**边缘**与**多轮**。 |

操作提示：使用 Playwright（或内置浏览器）打开测试页面，在输入框**手动**粘贴各用例文案发送，**不要**使用本仓库批量脚本代替人工观察。填写第 8 节表格时，建议同时记录是否出现 `generate_driver_report`、`consult_omni` 等，便于与产品预期对照。

## 4. 判定口径（召回 / 路由）

记录时建议用下列标签归纳（便于后续算召回与误路由）：

- **R+（单位报告应召回且正确）**：用户明确要**单位**（管理人员版安全总结 / 单位画像正式报告等）且目标单位可唯一落到「二巴公司」+ 分区 `20251221`（或系统等价理解），并进入单位报告生成流程（或合理澄清后进入）。
- **R−（单位报告应不召回）**：用户意图为**驾驶员个人报告**、仅咨询不生成报告、缺单位名、歧义多目标等，系统**不应**在信息不足或意图不符时强行生成「二巴公司」单位完整报告；acceptable 行为包括：澄清问句、走 `consult_omni`、或进入 `generate_driver_report`（当用户要的是任宇邦时）。
- **误路由（单位报告维度）**：在 R− 场景下仍调用单位报告并生成二巴公司报告，或在应生成单位报告时错误地走成仅咨询无报告、或错误地走驾驶员报告且无用户要驾驶员的表述。

> 说明：前端若展示 `执行Agent: generate_unit_report` / `router` / `consult_omni` 等，可作为辅助证据；最终以**用户可见结果**（是否像在走单位报告管线、槽位是否合理）为准。

## 6. 边缘用例（E1–E5）

### E1 — 应召回单位报告（R+）

- **新建会话**
- **用户输入（示例可微调用语，勿改「二巴公司」与分区）：**

```text
请生成二巴公司的单位安全风险分析总结报告（管理人员版），数据分区日期用 20251221。
```

- **预期**：识别为单位报告生成需求，针对「二巴公司」与分区 `20251221` 进入 `generate_unit_report` 管线（或极短确认后进入）；不应误走成任宇邦驾驶员报告。

### E2 — 应召回单位报告（R+）

- **新建会话**
- **用户输入：**

```text
帮我把二巴公司那份组织层面的安全管理总结拉出来，就要 20251221 这个分区对应的正式报告，别给个人版的。
```

- **预期**：「组织层面」「别给个人版」应强化单位管线；单位唯一（二巴公司）、分区明确；稳定路由至单位报告生成。

### E3 — 应不召回单位报告（R−，意图类型为驾驶员）

- **新建会话**
- **用户输入：**

```text
我要驾驶员任宇邦在分区 20251221 的驾驶员安全分析报告，要个人的那种，不要单位汇总。
```

- **预期**：应走向**驾驶员报告**（`generate_driver_report`），**不应**生成二巴公司单位报告。若本步仍出单位报告 → 记为对「单位管线」的误触发（负例失败）。

### E4 — 应不召回单位报告（R−，缺参）

- **新建会话**
- **用户输入：**

```text
20251221 这个分区帮我出一份单位的安全风险分析总结报告，管理人员版。
```

- **预期**：缺少具体单位名称，应追问「哪个单位」等，**不得**在无确认时默认填「二巴公司」并直接生成单位报告。

### E5 — 应不召回单位报告（R−，咨询非生成）

- **新建会话**
- **用户输入：**

```text
二巴公司在 20251221 分区整体风险高不高？先帮我解读下要点，不要生成完整正式报告，也不要排版成报告格式。
```

- **预期**：适合 `consult_omni` 类解读；**不应**调用 `generate_unit_report` 输出完整 JSON 报告。若用户明确否定「完整正式报告」，仍出长报告 → 记为误路由。

## 7. 多轮对话用例（M1–M5）

每例：**同一会话**内按顺序发送；**每一步发送后等待约 2 分钟**。

### M1 — 需求变更（无关 → 单位报告）

| 步骤 | 用户输入 |
|:---:|:---|
| 1 | `今天广州气温大概多少？` |
| 2 | `不说天气了。请按业务数据生成二巴公司在分区 20251221 的单位安全风险分析总结报告（管理人员版）。` |

- **预期**：第 1 步可拒答或简短说明范围；第 2 步应**切换**到单位报告意图，路由至 `generate_unit_report`，不因第 1 步污染。

### M2 — 信息分散（先单位名后分区）

| 步骤 | 用户输入 |
|:---:|:---|
| 1 | `我需要二巴公司那份管理人员用的安全总结。` |
| 2 | `分区日期是 20251221，刚才忘说了，请按这个分区生成正式报告。` |

- **预期**：第 2 步视为补参，最终应对「二巴公司 + 20251221」进入单位报告生成；中间不应因顺序导致退成纯咨询且无报告（除非产品明确如此）。

### M3 — 信息分散（先分区后单位名）

| 步骤 | 用户输入 |
|:---:|:---|
| 1 | `先看下 20251221 分区能出哪些类型的组织级报告。` |
| 2 | `那就给二巴公司出这个分区下的单位安全风险分析总结报告，管理人员版。` |

- **预期**：第 2 步锁定「二巴公司 + 20251221」，进入单位报告管线；第 1 步若为列举能力，第 2 步应能承接单位名。

### M4 — 追加解释（首轮模糊）

| 步骤 | 用户输入 |
|:---:|:---|
| 1 | `帮我做个管理视角的安全方面的材料。` |
| 2 | `是要单位组织层面的正式安全风险分析总结报告，单位是二巴公司，数据分区 20251221。` |

- **预期**：第 2 步消除歧义并进入 `generate_unit_report`；第 1 步允许追问，但若第 2 步已给全信息则不应无谓拖延。

### M5 — 纠错（错误分区 → 正确分区）

| 步骤 | 用户输入 |
|:---:|:---|
| 1 | `生成二巴公司的单位安全风险分析总结报告（管理人员版），分区 20251201。` |
| 2 | `分区写错了，应该是 20251221，请按这个分区重新生成单位报告。` |

- **预期**：第 2 步以纠正后的分区为准继续单位报告流程；若第 1 步因数据问题失败，第 2 步应能恢复并成功路由到单位报告（行为可与驾驶员/车辆报告多轮纠错类用例对照记录）。

### 9.1 执行记录（2026-04-12）

执行时间：2026-04-12 10:46–10:55（Asia/Shanghai）

### 9.2 统计结论

**召回率（狭义，单位报告）**：`6 / 7 = 85.7%`。  
R+ 目标轮为 E1、E2、M1、M2、M3、M4、M5，其中 M2 未正确召回。

**安全性（单位报告误触发）**：`0 / 3`。  
R− 用例 E3、E4、E5 均未误触发 `generate_unit_report`。

**主要问题**：M2 信息分散场景中，系统首轮已识别“二巴公司 + 管理人员安全总结”但要求补充信息；用户第二轮补充分区并明确“正式报告”后，路由没有承接单位报告上下文，转为驾驶员姓名澄清，属于多轮槽位保持/意图承接失败。
