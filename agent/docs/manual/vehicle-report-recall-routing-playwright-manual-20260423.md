# 车辆报告生成召回率与路由 Playwright 手动测试手册（4/23 批次）

日期：2026-04-23  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送用户消息  
测试目标：专项复检车辆报告生成管线的**召回率**（应进入 `generate_vehicle_report` 相关流程）、**不误召**（不应进入该管线）、**澄清行为**是否合理、以及长等待下的**系统稳定性**。本批次话术与 4/21 轮次不同，用于观察路由是否对表述漂移敏感。

样例数据来源：`agent/docs/mcp-usable-samples-20260410.md`（与 demo `fixtures` 一致）。

## 1. 测试范围（本轮不覆盖）

- 标准、规范的「请生成车辆安全风险分析总结报告 + 完整车牌 + 分区」等**正常表述**已在其他轮次验证，**本轮不测**。
- 本轮聚焦：**近义词 / 口语 / 错别字与不规范写法 / 中英混排 / 参数分散与澄清 / 易混意图**。

## 2. 数据约束（唯一允许）

仅允许使用以下两组真实数据（车牌与分区一一对应，勿改数字）：

```json
{ "numberplate": "粤A02650D", "ppartition": "20251221" }
```

```json
{ "numberplate": "粤A02013D", "ppartition": "20251221" }
```

与驾驶员样例交叉对照时，仅可使用同文档中的驾驶员姓名（用于**不应进入车辆报告**的负例）：`任宇邦`（工号`03001982`）、`关飞鸿`（工号`03001402`），分区仍为 `20251221`。

| 项   | 要求                                                                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------- |

## 4. 判定口径

### 4.1 权威判定依据：`metadata.tool`

**是否召回本管线**，以助手回复（或消息落库）中的 **`metadata.tool`** 为准，例如：

```json
"metadata": {
  "tool": "generate_vehicle_report"
}
```

未路由到具体工具时，`tool` 可能为 **空字符串 `""`**、缺省或其它工具名，以实际返回为准。

| 场景               | 对 `metadata.tool` 的要求                    |
| ------------------ | -------------------------------------------- |
| **应召回（R+）**   | 必须等于 **`generate_vehicle_report`**。     |
| **不应召回（R−）** | **不得**等于 **`generate_vehicle_report`**。 |

若页面「执行 Agent」与 `metadata.tool` 不一致，**以 `metadata.tool` 为判定依据**，并在备注中说明。

### 4.2 业务意图（与 §4.1 对照理解）

- **应召回（R+）**：用户真实意图为「指定车辆的正式车辆安全/管理向总结类报告」，且能落到上述两组 `(numberplate, ppartition)` 之一时，应进入车辆报告生成管线（含：先合理澄清缺参再进入）。
- **不应召回（R−）**：意图为**驾驶员**报告、**线路**报告、仅档案/属性查询、明确拒绝报告、多车对比/泛咨询等，**不得**进入车辆报告生成管线；acceptable 为澄清、`consult_omni`、基础查询、或进入 `generate_driver_report` / 线路相关能力（当用户明确要人/线时）等。

## 5. 十轮用例设计

### 5.1 应召回（5 例）— 近义词、口语、不规范表达、澄清后续跑通

| 轮次 | ID  | 考察点                               | 用户输入（可复制）                                                                                                                                               |
| :--: | :-- | :----------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|  1   | R+1 | 「报告」的近义：画像正式汇总         | **粤A02013D** 这台车，管理口要**安全画像正式汇总**，分区 **20251221**，按管理人员版出。                                                                          |
|  2   | R+2 | 口语化「车侧总结」                   | 把 **粤A02650D** **车侧安全总结**出了，就 **20251221** 这个档期，别给零散点评。                                                                                  |
|  3   | R+3 | 不规范：字母与数字间空格、斜杠日期   | 车牌 **粤A 02650D**（**粤**与 **A** 间无空格、**A** 与 **02650D** 间**一个空格**），要**车辆安全总结报告**；分区写 **2025/12/21**（看是否映射到 **20251221**）。 |
|  4   | R+4 | **澄清**：首轮缺参，次轮补全两组字段 | **Q1：** 我要**车辆管理视角**的安全汇总，字段给全、别缺模块。 **（等待回复后再发 Q2，仍在本会话）** **Q2：** 车 **粤A02013D**，分区 **20251221**。               |
|  5   | R+5 | 中英混排、fleet 表述                 | Fleet **safety management summary** for plate **粤A02650D**, **ppartition = 20251221**; management audience.                                                     |

**R+ 预期摘要：** 最终 `metadata.tool` 应为 **`generate_vehicle_report`**；R+4 允许第一轮仅澄清，第二轮补参后应命中该工具。
