## 4. 判定口径

- 成功召回：`tool` 命中预期报告 agent，例如 `generate_driver_report`、`generate_vehicle_report`、`generate_unit_report`。
- 未召回：返回 `consult_omni`、`router`、`null` 或其他非目标报告管线。
- 数据未命中但路由正确：如果落在目标报告 agent，只是报告内容提示“未找到数据”，仍算路由正确。
- 误路由：落入错误实体的报告 agent。本轮未出现明确误路由。

## 8. 问题分析

### 8.1 驾驶员与单位路由已明显改善

- 驾驶员两条消息都命中 `generate_driver_report`
- 单位两条消息都命中 `generate_unit_report`

这说明本次修改至少覆盖了“驾驶员画像风险报告”与“单位类报告”两类先前未命中的表达方式。

### 8.2 车辆画像风险报告仍未进入目标 agent

- `ID 3` 返回“未找到车辆 A32785D 在 2026年1月25日 的相关数据”
- 但 `tool = null`，没有进入 `generate_vehicle_report`

如果目标是“即使查无数据也应先进入车辆报告 agent 再给未命中提示”，则这条仍然失败。

### 8.3 线路两条请求仍未打通

- `ID 7` 返回“未找到线路527在2025年12月21日的风险报告数据”，`tool = null`
- `ID 8` 返回“未找到527路在2025年12月21日的风险总结报告”，`tool = null`

这表明线路类请求目前仍没有进入专门报告管线，而是直接在通用层给出“查无数据”响应。
