# 驾驶员报告生成召回率与路由 Playwright 手动测试手册

日期：2026-04-18  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送用户消息（不建议用自动化脚本批量发）  
测试目标：在**正常路径已验证通过**的前提下，专项检验驾驶员报告生成管线的**召回率**（应进入 `generate_driver_report` 相关流程）、**不误召**（不应进入该管线）、**澄清行为**是否合理、以及长等待下的**系统稳定性**。

样例数据来源：`agent/docs/mcp-usable-samples-20260410.md`（与 demo `fixtures` 一致）。

---

## 1. 测试范围（本轮不覆盖）

- 标准、规范的「请生成驾驶员安全报告 + 完整姓名/工号 + 分区」等**正常表述**已在其他轮次验证，**本轮不测**。
- 本轮聚焦：**近义词 / 口语 / 错别字与不规范写法 / 中英混排 / 参数分散与澄清**。

---

## 2. 数据约束（唯一允许）

仅允许使用以下两组真实数据（姓名、工号与分区一一对应，勿改数字与姓名）：

```json
{ "driverName": "任宇邦", "driverId": "03001982", "ppartition": "20251221" }
```

```json
{ "driverName": "关飞鸿", "driverId": "03001402", "ppartition": "20251221" }
```

与车辆样例交叉对照时，仅可使用同文档中的车牌（用于**不应进入驾驶员报告**的负例）：`粤A02650D`、`粤A02013D`，分区仍为 `20251221`。

---

## 3. 执行规范

| 项   | 要求                                                                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话 | **每一轮（R+1～R−5）单独新建会话**，避免上文干扰路由判定。                                                                                      |
| 等待 | 每发送**一条**用户消息后，**等待约 2 分钟**再读取助手回复（大模型较慢）；若界面出现「生成中」等中间态，可在最终文案出现后再补等数十秒确认落点。 |
| 记录 | 建议同时记录页面展示的 **执行 Agent / 工具名**（若可见，如 `generate_driver_report`）、是否出现错误页/超时/重试。                               |

---

## 4. 判定口径

- **应召回（R+）**：用户真实意图为「指定驾驶员的正式驾驶员安全/管理向总结类报告」，且能落到上述两组 `(driverName 或 driverId, ppartition)` 之一时，应进入驾驶员报告生成管线（含：先合理澄清缺参再进入）。
- **不应召回（R−）**：意图为**车辆**报告、仅档案/属性查询、明确拒绝报告、两名驾驶员对比/泛咨询等，**不得**进入驾驶员报告生成管线；acceptable 为澄清、`consult_omni`、基础查询、或进入 `generate_vehicle_report`（当用户明确要车时）等。

## 5. 十轮用例设计

### 5.1 应召回（5 例）— 近义词、口语、不规范表达、澄清后续跑通

| 轮次 | ID  | 考察点                               | 用户输入（可复制）                                                                                                                                                                |
| :--: | :-- | :----------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|  1   | R+1 | 「报告」的近义：总结 / 管理视角      | **任宇邦** 这位师傅我要一份**安全风险分析总结**，管理口看的，画像日期 **20251221**。                                                                                              |
|  2   | R+2 | 口语化、省略「生成」                 | **帮我整一下** **关飞鸿** **那位驾驶员**的安全方面材料，就 **20251221** 那天档期的。                                                                                              |
|  3   | R+3 | 不规范：空格、标点、日期口语         | 驾驶员 **任 宇邦**（中间有空格），要看**驾驶员安全总结报告**，时间：**2025年12月21号** 的画像（若系统只认 yyyyMMdd，看是否澄清或等价映射到 **20251221**）。                       |
|  4   | R+4 | **澄清**：首轮缺参，次轮补全两组字段 | **Q1：** 我想看**驾驶员管理人员版**那种安全总结，你帮我把版式出全。 **（等待回复后再发 Q2，仍在本会话）** **Q2：** 人是 **关飞鸿**，分区 **20251221**（工号 **03001402** 也可）。 |
|  5   | R+5 | 中英混排、partition 英文             | Please give me the **driver safety summary (management)** for **任宇邦**, **ppartition=20251221** (employee id **03001982** if needed).                                           |

**R+ 预期摘要：** 最终应走到驾驶员报告生成相关能力；R+4 允许第一轮仅澄清，第二轮补参后应进入管线。
