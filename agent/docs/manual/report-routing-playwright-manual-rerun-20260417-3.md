## 3. 执行规范

| 项目 | 要求 |
| --- | --- |
| 会话 | 每条测试消息新建独立 session |
| 浏览器 | Playwright + Chromium |
| 登录账号 | `user / user123` |
| 等待 | 串行执行，单条请求完成后再发送下一条，避免并发超时 |
| 记录 | 记录用户输入、会话标题、metadata.tool、回复摘要 |
| 判定依据 | 以 metadata 中的 `tool` / agent 是否命中目标报告管线为准 |

## 4. 判定口径

- 成功召回：`tool` 命中预期报告 agent，例如 `generate_driver_report`、`generate_vehicle_report`、`generate_unit_report`。
- 未召回：返回 `consult_omni`、`router`、`null` 或其他非目标报告管线。
- 数据未命中但路由正确：如果落在目标报告 agent，只是报告内容提示“未找到数据”，仍算路由正确。
- 误路由：落入错误实体的报告 agent。本轮未出现明确误路由。

## 7. 关键发现

### 7.1 驾驶员与单位对同义改写已经比较稳定

- 驾驶员 4 条新问法全部命中 `generate_driver_report`
- 单位 4 条新问法全部命中 `generate_unit_report`

这说明这两类报告不只对原始固定问法有效，对“拉一份 / 出具 / 生成 / 我要看 / 风险汇总”等改写也有较强鲁棒性。

### 7.2 车辆类对同义改写仍然脆弱

- 车辆画像风险报告两条都失败
- 车辆风险总结报告只有 1 条成功，另 1 条被打到 `consult_omni`

尤其是 `V-S-2` “我要看粤A32785D在2026年1月25日的安全风险汇总” 返回了明显的车辆风险总结正文，但 `tool = consult_omni`，说明车辆类仍然对措辞敏感。

### 7.3 线路类仍然没有稳定接入专门报告管线

- 两条线路画像报告都返回 `tool = null`
- 两条线路风险总结报告中，一条 `null`，一条 `consult_omni`
- `R-S-2` 虽然返回了完整“527路安全风险汇总”正文，但仍未进入线路报告管线

这说明线路类目前依然是“结果文案看起来像报告，但路由没有进目标 agent”的状态。

## 9. 结论

这轮“新问法鲁棒性”复测说明，当前系统已经明显分化成两档：

1. 驾驶员、单位：对同义改写已经比较稳，`100%` 命中
2. 车辆、线路：对同义改写仍明显脆弱，尤其线路仍是 `0%`

相比上一轮固定问法的 `5 / 8 = 62.5%`，这轮新问法的 `9 / 16 = 56.25%`，说明一旦放宽措辞，整体召回率会下滑，主要损失集中在车辆和线路。

如果继续改，建议优先排查：

1. 车辆类“安全风险汇总 / 画像风险分析 / 我要看”这类表达为何会退回 `consult_omni`
2. 车辆画像类在不带完整“粤”字前缀时，是否被过早判成实体不完整
3. 线路类是否根本缺少专门路由规则，导致只会落到 `null` 或 `consult_omni`
4. 对于已经产出报告正文但 `tool` 不对的场景，是否存在后处理兜底而非真实 agent 命中
