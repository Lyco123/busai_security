# 车辆专家话术贴合度 Playwright 手动测试手册

日期：2026-04-21  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送用户消息  
测试目标：验证当前“车辆专家”与《车辆画像 AI 通用话术（20260305）》的贴合度，区分：

- **路由是否正确**：应走 `consult_vehicle_expert`、`generate_vehicle_report` 还是其他链路
- **话术是否贴近**：是否贴近文档中的场景划分、回复深度、结构与措辞风格

---

## 1. 测试范围

本轮聚焦《车辆画像 AI 通用话术（20260305）》中的 4 类能力：

- 基础信息查询
- 风险分析
- 管理效果
- 安全风险分析总结报告

本轮**不强制要求**系统复现文档里的按钮、图表卡片、固定欢迎语；重点看：

- 是否进入正确链路
- 是否按对应场景给出相近深度
- 是否明显贴近文档中的结构与用语
- 是否出现越权、虚构、误走正式报告等偏差

## 3. 执行规范

| 项 | 要求 |
|---|---|
| 会话 | 除明确要求“同会话追问”的用例外，**每例单独新建会话** |
| 等待 | 每发一条消息后，**等待约 2 分钟**再读结果；若页面仍在生成，可补等 30-60 秒 |
| 记录 | 记录页面展示的 **执行 Agent**、关键回复摘要、是否有报错/超时 |
| 多轮 | 对多轮用例，必须按手册中的顺序继续追问，不要拆成新会话 |

## 4. 判定口径

### 4.1 路由判定

- **车辆咨询类**：应优先进入 `consult_vehicle_expert`
- **正式车辆总结报告类**：应进入 `generate_vehicle_report`
- **明确不是车辆正式报告/不是车辆主体**：不应进入 `generate_vehicle_report`，必要时也不应停留在 `consult_vehicle_expert`

### 4.2 话术贴合度判定

| 等级 | 判定标准 |
|---|---|
| 高 | 回复场景、深度和结构明显贴近文档；该短答时短答，该分析时分析；基本无明显风格偏差 |
| 中 | 路由正确，内容也基本可用，但未明显复用文档中的引导方式、结构骨架或关键措辞 |
| 低 | 虽有回答，但场景深度错位、明显偏离文档、越权、虚构，或把咨询误做成正式报告 |

### 4.3 单例通过标准

- **通过**：路由正确，且话术贴合度为“高”或“中”
- **失败**：路由错误，或虽路由正确但话术贴合度为“低”

## 7. 逐例记录模板

### V-S-1：入口型基础信息查询

用户输入：

```text
查询车牌号 粤A02650D 的车辆基础信息。
```

预期：

- 进入 `consult_vehicle_expert`
- 回复以事实信息为主，偏短答
- 可在末尾提示“可继续查看风险分析/管理效果/报告”，但不应直接生成正式报告

实测：

- 执行 Agent：`omni`
- 关键回复摘要：返回车辆自编号、车型、所属单位、注册日期、车龄、核载人数、车长、燃料类型、车架号等基础档案，并提示可继续查风险画像、预警记录、维保状态。
- 主观回复质量：好。信息完整、事实型短答为主，基本满足“基础信息查询”诉求。
- 主观判断理由：虽然字段比话术样例更杂、更长，但没有误生成正式报告，也没有无关分析。
- 与话术文档 alignment：中。结构接近“已为你查询到……基础信息如下”，也有后续引导；但未走车辆专家，且字段组织不完全贴近文档样式。
- 结论：失败。主要失败在路由层，不在回答可用性本身。

### V-S-2：分析后补充型基础信息

对话过程：

```text
Q1: 先帮我看看 粤A02013D 这台车的风险怎么样。
Q2: 那它的车辆基础信息是什么？
```

预期：

- 两轮都仍由车辆专家承接
- 第二轮能识别为“补充当前分析对象的基础信息”
- 不应丢失当前车辆上下文

实测：

- 执行 Agent：`Q1: vehicle_expert`；`Q2: omni`
- 关键回复摘要：
  - Q1 返回该车“整体风险较高”，强调能耗风险和驾驶不良行为，但出现“综合评分为 5 分（满分？），评价类型为安全型”的表述冲突。
  - Q2 返回车辆基础信息，但由 `omni` 承接，而不是继续沿用车辆专家上下文。
- 主观回复质量：不好。
- 主观判断理由：Q1 的数值和口径表达不稳定，Q2 虽能答出档案，但上下文承接失败，不符合“分析后补充型基础信息”预期。
- 与话术文档 alignment：低。文档要求第二轮识别为补充当前分析对象的基础信息；实测没有稳定维持同一专家承接。
- 结论：失败。

### V-S-3：故障风险单点咨询

用户输入：

```text
粤A02650D 这个车辆的故障风险情况如何？
```

预期：

- 进入 `consult_vehicle_expert`
- 回复应更接近“风险分析”而非“正式报告”
- 若系统不做文档里的引导追问，也至少应按单点解释或简版分析回答

实测：

- 执行 Agent：`vehicle_expert`
- 关键回复摘要：回答“故障风险总体较低”，给出单项得分、子项得分区间，并补充可关注空气压缩机参数是否符合常规工况。
- 主观回复质量：好。
- 主观判断理由：回复短、聚焦单点风险，不像正式报告，和用户问题匹配。
- 与话术文档 alignment：中。符合“单点解释/简版分析”方向，但没有复用文档中的引导追问或“综合分析一下”的交互骨架。
- 结论：通过。

### V-S-4：故障风险综合分析

用户输入：

```text
请对 粤A02013D 的故障风险做综合分析，我想看风险来源和建议。
```

预期：

- 进入 `consult_vehicle_expert`
- 回复应体现“结论 -> 依据 -> 风险来源 -> 建议动作 -> 数据缺口”或相近骨架
- 不应直接切到正式结构化报告

实测：

- 执行 Agent：`vehicle_expert`
- 关键回复摘要：按“结论、依据、风险来源、建议动作、数据缺口”结构展开，指出 ABS 故障、动力电池故障、轮胎温度报警及驾驶不良行为是主要风险来源。
- 主观回复质量：好。
- 主观判断理由：回答深度、展开方式和用户要的“综合分析+风险来源+建议”基本一致。
- 与话术文档 alignment：高。虽然没复刻示例话术的欢迎语和确认步骤，但分析骨架和深度明显贴近文档。
- 结论：通过。

### V-S-5：管理效果咨询

用户输入：

```text
粤A02650D 这个车辆的管理效果怎么样？
```

预期：

- 进入 `consult_vehicle_expert`
- 回复重点是管理状态、干预执行、效果变化或待处理风险
- 若当前数据不支持，应明确说明缺口；不得编造管理闭环细节

实测：

- 执行 Agent：`vehicle_expert`
- 关键回复摘要：把“管理效果”回答为“当前管理效果偏弱、关注型、总分 56 分”，主要展开的是能耗风险、故障风险和数据缺口，末尾建议继续查询风险追踪详情。
- 主观回复质量：不好。
- 主观判断理由：内容不是完全无用，但主体仍在说“当前风险画像/风险状态”，没有真正回答“管理是否闭环、措施是否执行、效果是否改善”。
- 与话术文档 alignment：低。文档中的管理效果话术强调“待接受建议、待确认处理、待优化风险、综合管理效果结论”，实测没有这些核心骨架。
- 结论：失败。

### V-S-6：报告后追问

对话过程：

```text
Q1: 请帮我生成 粤A02013D 在 20251221 的车辆安全风险分析总结报告。
Q2: 你刚才报告里提到的核心风险指标具体怎么理解？
```

预期：

- 第一轮进入 `generate_vehicle_report`
- 第二轮进入 `consult_vehicle_expert`
- 第二轮应解释报告中的指标，不应重复整份报告

实测：

- 执行 Agent：`Q1: generate_vehicle_report`；`Q2: omni`
- 关键回复摘要：
  - Q1 成功生成正式报告。
  - Q2 没有回到车辆专家，而是由 `omni` 详细解释“违规使用手刹、车辆起步不关车门、右电机故障、日充电次数”的含义和安全影响；页面中还出现了重复一遍用户提问。
- 主观回复质量：不好。
- 主观判断理由：Q2 解释本身有内容，但链路不对，而且重复消息表明交互稳定性一般。
- 与话术文档 alignment：低。manual 预期“报告后追问”回到车辆专家解释指标，不应继续停留在报告层之外的泛链路。
- 结论：失败。

### V-R-1：正式总结报告

用户输入：

```text
请帮我生成 粤A02650D 在 20251221 的车辆安全风险分析总结报告。
```

预期：

- 进入 `generate_vehicle_report`
- 成品结构应贴近文档中“安全风险分析总结报告回复模版——管理人员”
- 不应只返回普通咨询文本

实测：

- 执行 Agent：`generate_vehicle_report`
- 关键回复摘要：输出正式《车辆安全风险分析总结报告》，包含多维绩效看板、核心风险研判、行为与数据关联分析、针对性干预建议和附录。
- 主观回复质量：一般。
- 主观判断理由：结构是完整的，但正文存在“综合风险 0 分”“附录里车牌未知/车辆编号暂无”等明显质量问题，削弱成品可信度。
- 与话术文档 alignment：中。宏观结构明显对齐“管理人员版总结报告模板”，但细节填充质量和字段一致性不足。
- 结论：通过。

### V-R-2：明确不要报告

不要生成报告，只想确认 粤A02650D 在 20251221 有没有车辆画像数据。

- 主观判断理由：遵守“不要生成报告”的要求，回答短而直接。

- 结论：通过。

### V-R-4：两车对比口头结论

用户输入：

```text
对比 粤A02650D 和 粤A02013D 在 20251221 的风险情况，先给我口头结论，不要正式报告。
```

预期：

- 不进入 `generate_vehicle_report`
- 可澄清、可走咨询链路，但不应强行产出单车正式报告
- 若当前车辆专家无法合法处理双车对比，应明确说明边界

实测：

- 执行 Agent：`vehicle_expert`
- 关键回复摘要：只给出一句口头结论，说两车风险整体接近，并比较故障风险和能耗风险。

## 10. 本次结论

1. **路由层**
当前系统对“正式车辆总结报告”的分流相对稳定，`V-R-1` 与 `V-S-6/Q1` 都正确进入了 `generate_vehicle_report`。但“车辆专家内部的子场景分流”不够稳定，尤其是基础信息查询、分析后补充信息、报告后追问，仍会落到 `omni`。

2. **专家层**
`consult_vehicle_expert` 在“风险分析”和“综合分析”上表现最好，特别是 `V-S-4` 已明显贴近《车辆画像 AI 通用话术》的分析骨架；但在“基础信息查询”和“管理效果”两个场景上，对齐明显不足。也就是说，当前车辆专家更像是被调成了“风险分析专家”，而不是完整覆盖文档四类场景的“车辆画像话术专家”。

3. **报告层**
`generate_vehicle_report` 的成品结构整体贴近文档中的“管理人员版总结报告模板”，这部分对齐度明显高于专家问答层；但报告内部仍有字段质量问题，如“综合风险为 0”“附录车牌未知/车辆编号暂无”等，说明模板骨架已对齐，数据填充质量还没有完全对齐。

综合判断：**当前系统对话术文档的对齐主要集中在 `generate_vehicle_report` 和车辆专家的“风险分析类回答”，而不是完整覆盖 `consult_vehicle_expert` 的全部文档场景。** 更具体地说，当前车辆专家做了部分“回答深度控制型调教”，但还没有做到“按文档场景稳定分流 + 按场景骨架稳定回答”。
