# 驾驶员报告生成召回率与路由 Playwright 手动测试手册（4/23 批次）

日期：2026-04-23  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送用户消息（不建议用自动化脚本批量发，便于逐条观察路由与澄清）  
测试目标：专项检验驾驶员报告生成管线的**召回率**（应进入 `generate_driver_report` 相关流程）、**不误召**（不应进入该管线）、**澄清行为**是否合理、以及长等待下的**系统稳定性**。本批次用例表述与 4/18、4/21 轮次不同，用于回归路由是否随话术漂移。

样例数据来源：`agent/docs/mcp-usable-samples-20260410.md`（与 demo `fixtures` 一致）。

## 1. 测试范围（本轮不覆盖）

- 标准、规范的「请生成驾驶员安全报告 + 完整姓名/工号 + 分区」等**正常表述**已在其他轮次验证，**本轮不测**。
- 本轮聚焦：**近义词 / 口语 / 不规范写法 / 中英混排 / 参数分散与澄清 / 易混意图**。

## 2. 数据约束（唯一允许）

仅允许使用以下两组真实数据（姓名、工号与分区一一对应，勿改数字与姓名）：

```json
{ "driverName": "任宇邦", "driverId": "03001982", "ppartition": "20251221" }
```

```json
{ "driverName": "关飞鸿", "driverId": "03001402", "ppartition": "20251221" }
```

与车辆样例交叉对照时，仅可使用同文档中的车牌（用于**不应进入驾驶员报告**的负例）：`粤A02650D`、`粤A02013D`，分区仍为 `20251221`。

## 3. 执行规范

| 项   | 要求                                                                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话 | **每一轮（R+1～R−5）单独新建会话**，避免上文干扰路由判定。                                                                                      |
| 等待 | 每发送**一条**用户消息后，**等待约 2 分钟**再读取助手回复（大模型较慢）；若界面出现「生成中」等中间态，可在最终文案出现后再补等数十秒确认落点。 |
| 记录 | **必须**抄录助手消息中的 **`metadata.tool`**（见 §4.1）；可同时记录页面「执行 Agent」、错误页/超时/重试。                                       |

## 4. 判定口径

### 4.1 权威判定依据：`metadata.tool`

**是否召回本管线**，以助手回复（或消息落库）中的 **`metadata.tool`** 为准，形态为 JSON 里的字符串字段，例如：

```json
"metadata": {
  "tool": "generate_driver_report"
}
```

未路由到具体工具时，`tool` 可能为 **空字符串 `""`**、缺省或其它工具名（如 `consult_omni`），以实际返回为准。

| 场景               | 对 `metadata.tool` 的要求                                                      |
| ------------------ | ------------------------------------------------------------------------------ |
| **应召回（R+）**   | 必须等于 **`generate_driver_report`**（本手册对应的报告管线 Agent / 工具名）。 |
| **不应召回（R−）** | **不得**等于 **`generate_driver_report`**。                                    |

若页面展示的「执行 Agent」与 `metadata.tool` 不一致，**以 `metadata.tool` 为判定依据**，并在备注中写明 UI 表现。

### 4.2 业务意图（与 §4.1 对照理解）

- **应召回（R+）**：用户真实意图为「指定驾驶员的正式驾驶员安全/管理向总结类报告」，且能落到上述两组 `(driverName 或 driverId, ppartition)` 之一时，应进入驾驶员报告生成管线（含：先合理澄清缺参再进入）。
- **不应召回（R−）**：意图为**车辆**报告、**线路**报告、仅档案/属性查询、明确拒绝报告、两名驾驶员对比/泛咨询等，**不得**进入驾驶员报告生成管线；acceptable 为澄清、`consult_omni`、基础查询、或进入 `generate_vehicle_report` / 线路相关能力（当用户明确要车/线时）等。

| 轮次 | ID  | 考察点                               | 用户输入（可复制）                                                                                                                                                       |

|  2   | R+2 | 工号先行、口语化「材料」             | **03001982** 这位，帮出一份**车队长看的安全方面材料**，日期按 **20251221**，别给碎片化问答。                                                                             |
|  3   | R+3 | 日期分隔符、正式版表述               | **任宇邦**，管理人员版**驾驶员安全总结正式报告**，画像日期写成 **2025-12-21**（若系统只认 yyyyMMdd，看是否澄清或等价映射到 **20251221**）。                              |
