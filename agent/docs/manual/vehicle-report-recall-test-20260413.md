# 车辆报告生成召回率 Playwright 手动测试记录

日期：2026-04-13  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：Playwright 手动逐轮发送  
测试目标：验证车辆报告生成路由召回率，覆盖边缘情况与多轮对话处理。

## 1. 测试范围与目标

聚焦车辆报告路由的**应召回**与**不应召回**场景，以及多轮对话中的需求变更、补参、纠错与混合输入；不包含与上述无关的重复验证。

## 2. 数据约束

仅允许使用以下两组数据：

```json
{"numberplate": "粤A02650D", "ppartition": "20251221"}
```

```json
{"numberplate": "粤A02013D", "ppartition": "20251221"}
```

## 3. 执行规范

| 项 | 要求 |
|---|---|
| 会话 | 边缘用例（E1–E5）每例**新建会话**；多轮用例（M1–M5）在**同一会话**内按步骤发送。 |
| 等待 | 每发送一条用户消息后等待助手回复完成；若出现「生成中」类状态，可补等至最终落点。 |

## 4. 判定口径（召回）

- **应召回（R+）**：用户意图为指定车辆的正式安全/画像类报告，且参数可落到允许的两组车牌与分区之一时，应进入 `generate_vehicle_report` 或合理澄清后进入。
- **不应召回（R−）**：用户只要基础信息、明确否定报告、多车对比且非单报告意图等，**不应**进入 `generate_vehicle_report`；acceptable 行为包括澄清、`consult_omni`、基础查询等。

## 6. 边缘用例（E1–E5）

### E1. 隐式表达 — 应召回（R+）

**用户输入：**

```text
我想要看粤A02650D这辆车的安全分析，日期20251221
```

**预期：** 应进入 `generate_vehicle_report`，生成车辆安全报告。  
**理由：**「安全分析」虽未明说「报告」，但语义指向明确的报告需求。

### E2. 口语化表达 — 应召回（R+）

**用户输入：**

```text
帮我查一下粤A02013D这车有什么安全问题，看20251221的
```

**预期：** 应进入 `generate_vehicle_report`。  
**理由：**「安全问题」+「查一下」是口语化的报告需求表达。

### E3. 只查基本信息 — 不应召回（R−）

**用户输入：**

```text
粤A02650D这辆车的基本信息是什么，比如车型、所属公司这些
```

**预期：** 不应进入 `generate_vehicle_report`，应路由到基础查询或 `consult_omni`。  
**理由：** 用户明确只要「基本信息」，不是要报告。

### E4. 明确否定报告 — 不应召回（R−）

**用户输入：**

```text
我不要生成报告，只想确认粤A02013D在20251221有没有数据
```

**预期：** 不应进入 `generate_vehicle_report`。  
**理由：** 用户明确说「不要生成报告」。

### E5. 多车对比查询 — 不应召回（R−）

**用户输入：**

```text
对比一下粤A02650D和粤A02013D这两辆车的基本情况，日期都用20251221
```

**预期：** 不应进入 `generate_vehicle_report`，应澄清或走对比逻辑。  
**理由：**「基本情况」对比不是报告需求，且涉及两辆车需要澄清。

## 7. 多轮用例（M1–M5）

### M1. 需求变更：先要报告 → 改口不要

**对话过程：**

```text
Q1: 帮我生成粤A02650D的车辆安全报告，日期20251221
A1: [等待回复]

Q2: 等等，我改主意了，我其实只需要知道这辆车有没有运营资质
A2: [等待回复]
```

**预期：**

- A1 应进入 `generate_vehicle_report` 流程
- A2 应中止或转向其他查询，不应继续生成完整报告

### M2. 信息分散：意图 → 分散提供参数

**对话过程：**

```text
Q1: 我要看车辆报告
A1: [等待回复]

Q2: 车牌粤A02013D
A2: [等待回复]

Q3: 日期是20251221
A3: [等待回复]
```

**预期：** 应持续补参，最终进入 `generate_vehicle_report`。

### M3. 追加解释：报告生成中途补充条件

**对话过程：**

```text
Q1: 生成粤A02650D的车辆安全报告，日期20251221
A1: [等待回复]

Q2: 重点看安全违规这块，其他内容简略点就行
A2: [等待回复]
```

**预期：**

- A1 应进入 `generate_vehicle_report`
- A2 应在生成过程中调整或追加说明

### M4. 修正错误：错误车牌 → 用户纠正

**对话过程：**

```text
Q1: 生成车辆报告，车牌粤A99999D，日期20251221
A1: [等待回复]

Q2: 车牌我写错了，应该是粤A02650D
A2: [等待回复]

Q3: 日期还是20251221
A3: [等待回复]
```

**预期：**

- A1 应提示车牌无效或查无此车
- A2/A3 应正确修正并进入报告生成

### M5. JSON + 自然语言混合

**对话过程：**

```text
Q1: 帮我生成车辆报告
A1: [等待回复]

Q2: 车牌号是粤A02013D
A2: [等待回复]

Q3: {"ppartition":"20251221"}
A3: [等待回复]
```

**预期：** 应正确承接 JSON 片段补参，进入 `generate_vehicle_report`。
