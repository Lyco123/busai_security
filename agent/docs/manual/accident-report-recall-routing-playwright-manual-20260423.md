# 事故调查（整改）报告生成召回率与路由 Playwright 手动测试手册（4/23 批次）

日期：2026-04-23  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送用户消息  
测试目标：专项检验**事故调查 / 整改 / 复盘类正式报告**管线的**召回率**（应进入 `generate_accident_investigation_report`）、**不误召**（查询台账、基础信息、统计等不应走报告生成）、**澄清行为**是否合理、以及长等待下的**系统稳定性**。


---

## 1. 测试范围（本轮不覆盖）

- 标准、规范的「请生成事故调查报告 + 事故编号」等**一次性给全参数**表述可在其他轮次验证，**本轮不测**。
- 本轮聚焦：**近义词（调查/整改/复盘）/ 口语 / 别名与日期指代 / 中英混排 / 多轮补参 / 与「只查事故信息不要报告」的边界**。

---

## 2. 数据约束（唯一允许）

仅允许使用以下事故标识（与 fixtures 一致，勿改编号；自然语言可等价指向同一事故）：

```json
{ "incidentId": "INC-20251014-01" }
```

**可选用作口语指代的别名（与 local 一致，勿编造新事故）：**

- `2025-10-14 环市西路段刮碰事故`
- `2025-10-14`（仅在本环境中与上述事故唯一绑定时使用）
- `363路`（同上，用于考察歧义风险下的澄清；若环境允许多匹配则需记录实际行为）

与驾驶员报告交叉对照时，仅可使用同仓库样例中的驾驶员（用于**不应进入事故报告生成**的负例）：`任宇邦`（`03001982`）、分区 `20251221`（**不要**与事故 fixtures 混用为同一意图槽位，负例中明确只要驾驶员报告即可）。

## 4. 判定口径

### 4.1 权威判定依据：`metadata.tool`

**是否召回本管线**，以助手回复（或消息落库）中的 **`metadata.tool`** 字符串为准，例如：

```json
"metadata": {
  "tool": "generate_accident_investigation_report"
}
```

未路由到具体工具时，`tool` 可能为 **空字符串 `""`**、缺省、`consult_omni`、专家咨询类工具名等，以实际返回为准。

| 场景               | 对 `metadata.tool` 的要求                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------- |
| **应召回（R+）**   | 必须等于 **`generate_accident_investigation_report`**（事故调查/整改类报告管线对应的 Agent / 工具名）。 |
| **不应召回（R−）** | **不得**等于 **`generate_accident_investigation_report`**。                                             |

若 UI 展示与 `metadata.tool` 不一致，**以 `metadata.tool` 为判定依据**，并在备注中写明 UI 表现。

### 4.2 业务意图（与 `metadata.tool` 对照）

- **应召回（R+）**：用户明确要求生成**事故调查报告、整改报告、事故复盘报告**等**正式结构化报告**，且能落到 `INC-20251014-01` 或其允许的别名指代（含合理澄清后补全标识）。
- **不应召回（R−）**：用户只是在**查询事故信息、基础信息、详情、台账、列表、统计、处理进度**等，或明确**不要生成完整正式报告**、或意图为**驾驶员/车辆/线路等其它主体报告**时，**不得**进入 `generate_accident_investigation_report`。
