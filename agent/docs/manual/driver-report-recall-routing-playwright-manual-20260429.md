# 驾驶员报告生成召回率与路由 Playwright 手动测试手册（4/29 批次）

日期：2026-04-29  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送用户消息（不建议用自动化脚本批量发，便于逐条观察路由与澄清）  
测试目标：专项检验驾驶员报告生成管线的**召回率**（应进入 `generate_driver_report` 相关流程）、**不误召**（不应进入该管线）、**澄清行为**是否合理、以及长等待下的**系统稳定性**。本批次与 4/23 不同：**用户只提驾驶员姓名/工号，不提日期/分区，考察系统能否仅凭对象名完成路由与数据定位**。

样例数据来源：`agent/docs/mcp-usable-samples-20260410.md`（与 demo `fixtures` 一致）。

---

## 1. 测试范围（本轮不覆盖）

- 标准、规范的「请生成驾驶员安全报告 + 完整姓名/工号 + 分区」等**正常表述含分区**已在其他轮次验证，**本轮不测**。
- 本轮聚焦：**仅用驾驶员姓名/工号（不提日期分区）/ 近义词 / 口语 / 中英混排 / 参数分散与澄清 / 易混意图**。

## 2. 数据约束（唯一允许）

仅允许使用以下两组真实数据（姓名与工号一一对应，勿改数字与姓名）：

```json
{ "driverName": "任宇邦", "driverId": "03001982" }
```

```json
{ "driverName": "关飞鸿", "driverId": "03001402" }
```

与车辆样例交叉对照时，仅可使用同文档中的车牌（用于**不应进入驾驶员报告**的负例）：`粤A02650D`、`粤A02013D`。

**本轮不提分区 `ppartition`**，用户输入中仅用驾驶员姓名或工号指代对象。

| 项   | 要求                                                                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话 | **每一轮（R+1～R−5）单独新建会话**，避免上文干扰路由判定。                                                                                      |

## 4. 判定口径

### 4.1 权威判定依据：`metadata.tool`

**是否召回本管线**，以助手回复（或消息落库）中的 **`metadata.tool`** 为准，形态为 JSON 里的字符串字段，例如：

```json
"metadata": {
  "tool": "generate_driver_report"
}
```

未路由到具体工具时，`tool` 可能为 **空字符串 `""`**、缺省或其它工具名（如 `consult_omni`），以实际返回为准。

| 场景               | 对 `metadata.tool` 的要求                                                      |
| ------------------ | ------------------------------------------------------------------------------ |
| **应召回（R+）**   | 必须等于 **`generate_driver_report`**（本手册对应的报告管线 Agent / 工具名）。 |
| **不应召回（R−）** | **不得**等于 **`generate_driver_report`**。                                    |

若页面展示的「执行 Agent」与 `metadata.tool` 不一致，**以 `metadata.tool` 为判定依据**，并在备注中写明 UI 表现。

### 4.2 业务意图（与 §4.1 对照理解）

- **应召回（R+）**：用户真实意图为「指定驾驶员的正式驾驶员安全/管理向总结类报告」，且能落到上述两组 `(driverName 或 driverId)` 之一时，应进入驾驶员报告生成管线（含：先合理澄清缺参再进入）。本轮用户**不提日期分区**，系统需仅凭驾驶员标识完成路由；若系统需分区参数，允许澄清追问。
- **不应召回（R−）**：意图为**车辆**报告、**线路**报告、仅档案/属性查询、明确拒绝报告、两名驾驶员对比/泛咨询等，**不得**进入驾驶员报告生成管线；acceptable 为澄清、`consult_omni`、基础查询、或进入 `generate_vehicle_report` / 线路相关能力（当用户明确要车/线时）等。

## 5. 十轮用例设计

### 5.1 应召回（5 例）— 仅姓名/工号、不提日期

| 轮次 | ID  | 考察点                              | 用户输入（可复制）                                                                                                                                    |
| :--: | :-- | :---------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------- |
|  1   | R+1 | 「报告」的近义：履职汇总 / 管理视角 | 管理侧要看 **关飞鸿** 师傅的**安全履职情况汇总**，别给碎片化问答。                                                                                    |
|  2   | R+2 | 工号先行、口语化「材料」            | **03001982** 这位，帮出一份**车队长看的安全方面材料**，别给碎片化问答。                                                                               |
|  3   | R+3 | 姓名直接、正式版表述                | **任宇邦**，管理人员版**驾驶员安全总结正式报告**。                                                                                                    |
|  4   | R+4 | **澄清**：首轮缺参，次轮补全姓名    | **Q1：** 我想出一份**驾驶员侧**的安全汇总，版式要齐、别漏模块。 **（等待回复后再发 Q2，仍在本会话）** **Q2：** 驾驶员 **关飞鸿**，工号 **03001402**。 |
|  5   | R+5 | 中英混排、briefing 表述             | Need a **driver safety briefing (management)** for **任宇邦**; use employee id **03001982** if the name is ambiguous.                                 |

**R+ 预期摘要：** 最终 `metadata.tool` 应为 **`generate_driver_report`**；R+4 允许第一轮仅澄清，第二轮补参后应命中该工具。若系统追问分区，用户可补分区（记在备注），但判定仍以最终 `metadata.tool` 为准。

### 5.2 不应召回（5 例）— 易混意图、否定、双人、无驾驶员主体

| 轮次 | ID  | 考察点                                   | 用户输入（可复制）                                                                |
| :--: | :-- | :--------------------------------------- | :-------------------------------------------------------------------------------- |
|  6   | R−1 | 易混：**线路**安全总结 vs 驾驶员报告     | 我要**线路**安全总结，**527路**，全程别提驾驶员姓名。                             |
|  7   | R−2 | 明确不要「报告」，点状信息               | **别出长篇报告**，只要 **03001982** 的**当班线路编号**这类**点点信息**。          |
|  8   | R−3 | 仅确认数据是否存在（非报告）             | **不要生成报告**。请确认 **关飞鸿**（**03001402**）**有没有驾驶员画像数据**就行。 |
|  9   | R−4 | 两人 + 对比/概况（非单人长篇报告管线）   | **任宇邦** 和 **关飞鸿** **横向比一下**，**不要只给一个人的正式长篇报告**。       |
|  10  | R−5 | 无具体驾驶员、泛问题（测不误召与稳定性） | 公交司机日常安全培训一般抓哪些重点？**先不说具体哪个人。**                        |

**R− 预期摘要：** `metadata.tool` **不得**为 **`generate_driver_report`**；可出现澄清、车辆/线路报告、其他 Agent、或通用问答。
