# 车辆报告生成召回率与路由 Playwright 手动测试手册（4/21 复测）

日期：2026-04-21  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送用户消息  
测试目标：在**4/18复测显示车辆管线路由退化到0%**的前提下，专项复检车辆报告生成管线的**召回率**（应进入 `generate_vehicle_report` 相关流程）、**不误召**（不应进入该管线）、**澄清行为**是否合理、以及长等待下的**系统稳定性**。

样例数据来源：`agent/docs/mcp-usable-samples-20260410.md`（与 demo `fixtures` 一致）。

---

## 1. 测试范围（本轮不覆盖）

- 标准、规范的「请生成车辆安全风险分析总结报告 + 完整车牌 + 分区」等**正常表述**已在其他轮次验证，**本轮不测**。
- 本轮聚焦：**近义词 / 口语 / 错别字与不规范写法 / 中英混排 / 参数分散与澄清 / 易混意图**。

---

## 2. 数据约束（唯一允许）

仅允许使用以下两组真实数据（车牌与分区一一对应，勿改数字）：

```json
{ "numberplate": "粤A02650D", "ppartition": "20251221" }
```

```json
{ "numberplate": "粤A02013D", "ppartition": "20251221" }
```

与驾驶员样例交叉对照时，仅可使用同文档中的驾驶员姓名（用于**不应进入车辆报告**的负例）：`任宇邦`（工号`03001982`）、`关飞鸿`（工号`03001402`），分区仍为 `20251221`。

## 3. 执行规范

| 项   | 要求                                                                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话 | **每一轮（R+1～R−5）单独新建会话**，避免上文干扰路由判定。                                                                                      |
| 等待 | 每发送**一条**用户消息后，**等待约 2 分钟**再读取助手回复（大模型较慢）；若界面出现「生成中」等中间态，可在最终文案出现后再补等数十秒确认落点。 |
| 记录 | 建议同时记录页面展示的 **执行 Agent / 工具名**（若可见）、是否出现错误页/超时/重试。                                                            |

---

## 4. 判定口径

- **应召回（R+）**：用户真实意图为「指定车辆的正式车辆安全/管理向总结类报告」，且能落到上述两组 `(numberplate, ppartition)` 之一时，应进入车辆报告生成管线（含：先合理澄清缺参再进入）。
- **不应召回（R−）**：意图为**驾驶员**报告、仅档案/属性查询、明确拒绝报告、多车对比/泛咨询等，**不得**进入车辆报告生成管线；acceptable 为澄清、`consult_omni`、基础查询、或进入 `generate_driver_report`（当用户明确要驾驶员时）等。

### 5.1 应召回（5 例）— 近义词、口语、不规范表达、澄清后续跑通

|  2   | R+2 | 口语化、省略「生成」                 | **帮我整一下** **粤A02013D** **那车**的安全方面材料，就 **20251221** 天档期的。                                                                            |
|  3   | R+3 | 不规范：空格、标点、日期口语         | 车牌 **粤A 02650D**（中间有空格），要看**车辆安全总结报告**，时间：**2025年12月21号** 的画像（若系统只认 yyyyMMdd，看是否澄清或等价映射到 **20251221**）。 |

**R+ 预期摘要：** 最终应走到车辆报告生成相关能力；R+4 允许第一轮仅澄清，第二轮补参后应进入管线。

## 8. 小结模板（可选）

- 应召回成功数 /5：**4/5**
- 不应召回成功数 /5：**5/5**
- 主要失败模式（若有）：R+3车牌中间有空格（"粤A 02650D"）导致实体识别失败，系统返回tool=null而非进入报告管线。与线路R+3（"5 27"空格仍能识别）形成对比，说明车辆管线对车牌格式更敏感。

**变化**：车辆报告管线从4/18的0%召回率恢复到4/21的80%（4/5应召回成功），主要改善在于"安全风险分析总结"、"帮我整一下"等近义/口语表达已能正确路由。唯一失败点为车牌格式不规范场景。

## 9. 用例设计依据

本 manual 依据当前车辆报告管线的路由规则设计，参考：

- 驾驶员报告召回手册 `agent/docs/manual/driver-report-recall-routing-playwright-manual-20260418.md`
- 车辆报告召回手册 `agent/docs/manual/vehicle-report-recall-routing-playwright-manual-20260414.md`
- 车辆报告召回测试 `agent/docs/manual/vehicle-report-recall-test-20260414.md`
- 综合路由复测 `agent/docs/manual/report-routing-playwright-manual-rerun-20260418.md`

历史结论：车辆报告管线在 4/18 最新复测中召回率为 **0%**（两条都未进入 `generate_vehicle_report`），较 4/17 的 50% 明显退化。4/14 专项测试显示含关键词时 100%，不含关键词时仅 14%。

**本轮（4/21）结论**：车辆报告管线召回率恢复到 **80%**（4/5应召回成功+5/5不应召回成功），较4/18的0%有显著改善。唯一失败点为车牌格式不规范（空格）场景，建议后续优化车牌实体识别的容错能力。
