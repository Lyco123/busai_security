## 4. 判定口径

- 成功召回：`tool` 命中预期报告 agent，例如 `generate_driver_report`、`generate_vehicle_report`、`generate_unit_report`。
- 未召回：`tool = null`，或返回的不是目标报告管线。
- 数据未命中但路由正确：若进入目标报告 agent，只是内容提示未找到数据，仍算路由正确。
- 误路由：落入错误实体的报告 agent，或实体正确但报告类型明显错位。

## 7. 关键发现

### 7.1 驾驶员类只保证了“进驾驶员管线”，未严格区分画像/总结

- `ID 1` 命中 `generate_driver_report`，但返回的是“驾驶员安全风险分析总结报告”，不是画像报告。
- `ID 2` 同样命中 `generate_driver_report`，且与用户要的“风险总结报告”一致。

结论：驾驶员实体召回稳定，但“画像”和“总结”没有被前端可见结果区分开。

### 7.2 车辆两条都没有召回到车辆报告管线

- `ID 3` 回复“未找到车牌号为 A32785D 的车辆信息”，`tool = null`
- `ID 4` 回复“未找到车牌号为粤A32785D的车辆信息”，`tool = null`

和 2026-04-17 上午的 rerun 相比，本次 `ID 4` 从“可进 `generate_vehicle_report`”退化为“直接未召回”。

### 7.3 单位两条仍稳定

- `ID 5`、`ID 6` 都命中 `generate_unit_report`
