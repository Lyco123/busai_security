# 线路报告生成召回率与路由 Playwright 手动测试手册（4/23 批次）

日期：2026-04-23  
测试页面：`https://busodemo.canocache.com/assistant`  
执行方式：**Playwright 手动**逐条发送用户消息  
测试目标：专项检验线路报告生成管线的**召回率**（应进入线路报告生成相关流程）、**不误召**（不应进入该管线）、**澄清行为**是否合理、以及长等待下的**系统稳定性**。本批次话术与 4/21 轮次不同，用于回归「线路 vs 车/驾驶员」边界。

样例数据来源：`agent/docs/mcp-usable-samples-20260410.md`（与 demo `fixtures` 一致）。

## 1. 测试范围（本轮不覆盖）

- 标准、规范的「请生成线路安全风险分析总结报告 + 线路名 + 分区」等**正常表述**已在其他轮次验证，**本轮不测**。
- 本轮聚焦：**近义词 / 口语 / 不规范写法 / 中英混排 / 参数分散与澄清 / 易混意图**。

## 2. 数据约束（唯一允许）

仅允许使用以下线路数据（线路名与分区一一对应，勿改数字）：

```json
{ "routeName": "527", "ppartition": "20251221" }
```

与车辆样例交叉对照时，仅可使用同文档中的车牌（用于**不应进入线路报告**的负例）：`粤A02650D`、`粤A02013D`，分区仍为 `20251221`。

## 4. 判定口径

### 4.1 权威判定依据：`metadata.tool`

**是否召回本管线**，以助手回复（或消息落库）中的 **`metadata.tool`** 为准，例如：

```json
"metadata": {
  "tool": "generate_route_report"
}
```

未路由到具体工具时，`tool` 可能为 **空字符串 `""`**、缺省或其它工具名，以实际返回为准。

| 场景               | 对 `metadata.tool` 的要求                  |
| ------------------ | ------------------------------------------ |
| **应召回（R+）**   | 必须等于 **`generate_route_report`**。     |
| **不应召回（R−）** | **不得**等于 **`generate_route_report`**。 |

若页面「执行 Agent」与 `metadata.tool` 不一致，**以 `metadata.tool` 为判定依据**，并在备注中说明。

### 4.2 业务意图（与 §4.1 对照理解）

- **应召回（R+）**：用户真实意图为「指定线路的正式线路安全/管理向总结类报告」，且能落到 `routeName = 527, ppartition = 20251221` 时，应进入线路报告生成管线（含：先合理澄清缺参再进入）。
- **不应召回（R−）**：意图为**车辆**报告、仅属性查询、明确拒绝报告、多线路对比/泛咨询等，**不得**进入线路报告生成管线；acceptable 为澄清、`consult_omni`、基础查询、或进入 `generate_vehicle_report`（当用户明确要车时）等。

|  3   | R+3 | 「527路」带路字 + 中文日期           | **527路** 的**线路安全总结报告**，日期：**二〇二五年十二月二十一日**（看是否澄清或等价映射到 **20251221**）。                  |
|  4   | R+4 | **澄清**：首轮缺参，次轮补全两组字段 | **Q1：** 我要**线路级**的安全总结，模块别缺。 **（等待回复后再发 Q2，仍在本会话）** **Q2：** 线路 **527**，分区 **20251221**。 |
