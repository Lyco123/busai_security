# 本地模型服务实现方案（极简版）

本次模型服务方案如下：

- 文本模型：`Qwen/Qwen3.5-35B-A3B`
- Embedding 模型：`Qwen/Qwen3-Embedding-0.6B`
- 推理框架：`vLLM`
- 暴露协议：`OpenAI-compatible API`

## 1. 服务拆分

建议拆成 3 个服务入口：

- 文本模型服务：`http://<host>:8000/v1`
- Embedding 模型服务：`http://<host>:8001/v1`
- 统一网关：`http://<host>:9000/v1`

其中：

- `:8000` 负责文本生成
- `:8001` 负责向量化
- `:9000` 作为统一对外入口

统一网关只做转发：

- `/v1/chat/completions` -> `:8000`
- `/v1/embeddings` -> `:8001`

## 2. 对外暴露接口

### 2.1 文本模型服务

需要提供：

- `POST /v1/chat/completions`

需要兼容以下能力：

- `model`
- `messages`
- `temperature`
- `stream`
- `tools`
- `tool_choice`
- `response_format: { "type": "json_object" }`

返回结构至少兼容：

- `choices[0].message.content`
- `choices[0].message.tool_calls`

### 2.2 Embedding 模型服务

需要提供：

- `POST /v1/embeddings`

请求字段至少兼容：

- `model`
- `input`

返回结构至少兼容：

- `data[0].embedding`

本次 embedding 维度采用 `1024`。

## 3. 最简部署方式

### 3.1 文本模型

```bash
vllm serve Qwen/Qwen3.5-35B-A3B \
  --host 0.0.0.0 \
  --port 8000 \
  --tensor-parallel-size 8 \
  --max-model-len 262144 \
  --reasoning-parser qwen3 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3 \
  --language-model-only
```

注意：业务侧会发送 OpenAI-compatible tools 和 `tool_choice: "auto"`，因此文本模型服务必须启用 auto tool choice，并配置与 Qwen3/Qwen3.5 兼容的 tool call parser；否则 `/v1/chat/completions` 会返回 400。

### 3.2 Embedding 模型

```bash
vllm serve Qwen/Qwen3-Embedding-0.6B \
  --host 0.0.0.0 \
  --port 8001 \
  --task embed
```

## 4. 对外接入方式

建议业务侧统一访问：

- `http://<host>:9000/v1`

由统一网关按接口转发到文本模型服务或 embedding 模型服务。

## 5. 一句话结论

本次实现方案是：使用 `vLLM` 分别部署文本模型和 embedding 模型，再通过统一网关对外暴露一套 OpenAI 兼容接口。
