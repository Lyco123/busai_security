# 本地模型替换后编排层改动与重部署清单（极简版）

目标方案：

- 文本模型：`Qwen/Qwen3.5-35B-A3B`
- Embedding 模型：`Qwen/Qwen3-Embedding-0.6B`
- Embedding 维度：`1024`

## 1. 模型服务侧

需要新增或重配：

- 部署文本模型服务 `:8000`
- 部署 embedding 模型服务 `:8001`
- 部署统一网关 `:9000`
- 统一网关转发 `/v1/chat/completions` 和 `/v1/embeddings`

## 2. Agent 主服务配置改动

需要修改：

- `OPENAI_BASE_URL`
- `OPENAI_MODEL`
- `OPENAI_ROUTER_MODEL`
- `OPENAI_WORKER_MODEL`
- `OPENAI_EMBEDDING_MODEL`
- `OPENAI_API_KEY`

说明：

- 当前 Agent 主服务没有独立的 `OPENAI_EMBEDDING_BASE_URL`
- 因此如果不改代码，就必须通过统一网关同时提供 chat 和 embeddings

## 3. Retrieval 服务配置改动

需要修改：

- `LLM_BASE_URL`
- `LLM_API_KEY`
- `EMBEDDING_BASE_URL`
- `EMBEDDING_API_KEY`
- `EMBEDDING_MODEL`
- `EMBED_DIM`

按需确认：

- `QUERY_REWRITE_MODEL`
- `RERANK_MODEL`

说明：

- 如果检索侧改写/重排也切到本地文本模型，需要同步改 `LLM_BASE_URL` 和模型名
- 如果这两项暂时继续走原服务，需要明确保留原配置，不要半切换

## 4. 向量数据库与索引重建

必须处理：

- Qdrant collection 维度从 `1536` 切到 `1024`
- 旧 collection 不能直接复用
- 需要删除并重建 collection，或切换到新的 collection 名
- 所有知识库向量需要重新生成
- 所有知识库索引任务需要重新跑

## 5. Retrieval 数据重建

必须处理：

- 重启 retrieval API
- 重启 retrieval worker
- 触发全量 `reindex`
- 等待 `kb_index_jobs` 消费完成
- 确认 `vector_status` 恢复为 `ready`

## 6. Rules / Scenarios embedding 重刷

必须处理：

- `rules` 表历史 embedding 需要全量重刷
- `work_scenarios` 表历史 embedding 需要全量重刷

原因：

- 当前历史数据是按旧 embedding 模型和旧维度生成的
- 新旧向量不能混用做相似度匹配

## 7. 部署与重启范围

需要重新部署或重启：

- 文本模型服务
- embedding 模型服务
- 统一网关
- Agent 主服务
- retrieval API
- retrieval worker
- Qdrant

如使用容器化部署，还需要同步更新：

- `docker-compose`
- `env_file`
- 服务启动命令
- 健康检查与端口映射

## 8. 验证项

至少验证：

- `/v1/chat/completions` 可用
- `/v1/embeddings` 可用
- embedding 返回长度为 `1024`
- Agent 主对话可用
- Router / Worker 可用
- rules 匹配可用
- scenarios 匹配可用
- retrieval 检索可用
- reindex 可用
- Qdrant 检索结果正常

## 9. 风险点

需要接受的变化：

- 向量维度从 `1536` 变为 `1024`
- 检索召回质量可能与现有 DashScope `text-embedding-v1` 不完全一致
- rules/scenarios 的匹配阈值可能需要回归验证
- retrieval 的 query rewrite / rerank 如果一并切本地，效果也需要重新验证
