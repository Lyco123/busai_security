# 方案二：后端服务本地部署方案

## 1. 背景与目标
为满足 **对外展示 (Demo)** 和 **重要交付** 的需求，需要将稳定的大版本后端服务部署在项目组自有的高性能服务器上。

## 2. 架构设计

我们将采用基于 **Docker 容器化** 的微服务架构，在自有服务器上运行完整的后端技术栈。

### 2.1 核心特性
*   **运行环境**: Docker 容器 (Node.js/Python)
*   **数据库**: PostgreSQL (主数据) + Redis (缓存/队列)
*   **大模型调用**: 调用本地 vLLM 接口 (内网低延迟)
*   **更新频率**: 按版本发布 (人工/Tag 触发)

### 2.2 服务拓扑
```mermaid
graph TD
    User[外部用户/演示端] --> Nginx[Nginx 网关 (SSL/Auth)]
    Nginx --> Backend[Agent 后端服务 (Node.js)]
    Backend --> DB[(PostgreSQL)]
    Backend --> Redis[(Redis 缓存/队列)]
    Backend --> LLM[本地大模型服务 (vLLM)]
```

## 3. 部署配置详解 (Docker Compose)

我们使用 `docker-compose` 进行服务编排，确保一键启动和环境一致性。

### 3.1 容器编排 (docker-compose.yml)
```yaml
version: '3.8'
services:
  # 网关层：处理 HTTPS 和 静态资源
  gateway:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d
      - ./certs:/etc/nginx/certs
    depends_on:
      - agent-backend

  # 业务逻辑层：Agent 核心代码
  agent-backend:
    build: .
    environment:
      - NODE_ENV=production
      - DATABASE_URL=postgresql://user:pass@db:5432/agent_db
      - LLM_API_BASE=http://host.docker.internal:8000/v1  # 指向宿主机 vLLM
      - REDIS_URL=redis://redis:6379
    restart: always
    depends_on:
      - db
      - redis

  # 数据持久层
  db:
    image: postgres:15
    volumes:
      - db_data:/var/lib/postgresql/data
    environment:
      - POSTGRES_PASSWORD=secure_password
  
  # 缓存层
  redis:
    image: redis:alpine
    volumes:
      - redis_data:/data

volumes:
  db_data:
  redis_data:
```

### 3.2 代码适配 (Node.js Adapter)
为了在 Docker 容器中运行，需确保代码入口适配 Node.js 环境：
*   **入口文件**: 创建 `index.node.ts` (或类似入口)，使用 **Fastify** 或 **Hono (@hono/node-server)** 启动 HTTP Server。
*   **环境变量**: 确保所有配置项（如数据库连接串、API Key）均从 `process.env` 读取，而非硬编码。

## 4. CI/CD 流水线设计 (GitHub Actions)

通过 CI/CD 自动化管理发布流程，确保演示环境的稳定性。

**Trigger**: Push `v*.*.*` Tag (发布版本)

**流程步骤**:
1.  **构建**: 基于 `Dockerfile` 构建后端镜像，打上对应 Tag。
2.  **推送**: 将镜像推送到私有镜像仓库 (如 GHCR)。
3.  **部署**: 
    *   SSH 连接到自有服务器。
    *   更新 `docker-compose.yml` 中的镜像版本。
    *   执行 `docker-compose pull && docker-compose up -d` 重启服务。

## 5. 数据管理策略

*   **配置数据**: Prompt 模板和规则配置建议存储在代码仓库或挂载的配置文件中，随镜像更新。
*   **业务数据**: 
    *   所有对话日志、用户数据存储在本地 PostgreSQL 容器中。
    *   **备份**: 设置定时任务 (Cron Job) 每日备份数据库 Dump 文件到指定目录或冷存储。

## 6. 实施建议

1.  **内网穿透**: 如果自有服务器没有公网 IP，推荐使用 **Cloudflare Tunnel (cloudflared)** 将本地服务安全暴露给外部演示，无需配置复杂的防火墙规则。
2.  **日志监控**: 建议集成简单的日志查看工具 (如 Dozzle) 或将日志输出到文件，便于排查演示过程中可能出现的问题。
3.  **资源限制**: 在 `docker-compose` 中为每个服务设置 `deploy.resources.limits`，防止某个服务占用过多 CPU/内存影响大模型推理。
