## 参考设计：抽象查询接口（推荐实现）

### 适用范围

本文给出一个更完整、更工程化的“抽象查询接口”参考设计，用于交信投侧评审/落地。它兼容我方现状 `query_data` 的最小能力集，同时补齐生产级接口常见要素（分页、过滤、鉴权、错误码、演进机制）。

### 1. 设计目标与原则

- **抽象稳定**：接口形态稳定，不随业务报表/场景数量膨胀
- **可扩展**：新增实体类型/字段时不新增 endpoint，只扩展 schema 注册
- **可观测/可治理**：支持审计、限流、权限控制、版本演进
- **对齐工具层**：天然适配 LLM Tool Calling / MCP 风格（`tools/list` + `tools/call` 的思想）

### 2. 接口形态（推荐）

#### 2.1 数据查询（单一入口）

```
POST /api/query/data
Content-Type: application/json
Accept: application/json
```

#### 2.2 Schema 获取（可选：独立 endpoint）

> 如果希望对外更“REST”，也可单独提供 schema endpoint；否则用 `action=describe` 即可。

```
GET /api/query/schema?entity_type=driver
Accept: application/json
```

### 3. 请求模型（推荐）

#### 3.1 Request Body

```json
{
  "action": "describe | list | get | search",
  "entity_type": "driver | vehicle | route",
  "entity_id": "string",
  "search_term": "string",
  "fields": ["basic.driver_name", "risk_profile.overall"],
  "filters": [
    { "field": "risk_profile.level", "op": "eq", "value": "high" },
    { "field": "basic.fleet_name", "op": "in", "value": ["一车队", "二车队"] }
  ],
  "sort": [{ "field": "risk_profile.overall", "order": "desc" }],
  "page": { "limit": 20, "cursor": "opaque_cursor" },
  "trace_id": "optional-client-trace-id"
}
```

#### 3.2 字段语义约束

- **`fields`（投影）**：
  - 只允许访问 schema 注册过的字段路径（避免越权/误取）
  - 未传则返回“默认字段集”（而非全量），以控制带宽与隐私暴露
- **`filters`（过滤）**：
  - 采用结构化表达，避免拼 SQL / 字符串 DSL 注入风险
  - `op` 推荐支持：`eq/ne/gt/gte/lt/lte/in/contains/prefix`
- **分页**：
  - 推荐 **cursor 分页**（稳定/性能好），同时兼容 offset 分页（可选）
  - `limit` 最大值建议 50（与我方现状一致）

### 4. 响应模型（推荐）

#### 4.1 通用 Envelope

```json
{
  "success": true,
  "data": {},
  "meta": {
    "trace_id": "server-trace-id",
    "entity_type": "driver",
    "action": "list"
  }
}
```

#### 4.2 字段级部分成功（推荐）

当 `fields` 投影中**部分字段**因权限/脱敏策略/数据缺失不可返回时，建议仍返回 `success=true`，并在响应中显式标注失败字段；`data` 仅包含成功字段。

```json
{
  "success": true,
  "data": {
    "basic": { "driver_name": "张三" }
  },
  "field_errors": [
    { "field": "risk_profile.overall", "code": "FORBIDDEN", "message": "字段无权限" },
    { "field": "health", "code": "NOT_AVAILABLE", "message": "字段暂不可用" }
  ],
  "meta": { "trace_id": "server-trace-id", "entity_type": "driver", "action": "get" }
}
```

失败：

```json
{
  "success": false,
  "error": {
    "code": "INVALID_ARGUMENT",
    "message": "entity_type is required for list action",
    "details": { "field": "entity_type" }
  },
  "meta": { "trace_id": "server-trace-id" }
}
```

#### 4.3 list/search 的分页返回

```json
{
  "success": true,
  "data": {
    "items": [{ "id": "driver_001", "name": "张三", "identifier": "D001" }],
    "page": { "limit": 20, "next_cursor": "opaque_cursor_or_null" },
    "total": 150
  },
  "meta": { "entity_type": "driver", "action": "list" }
}
```

### 5. action 定义（推荐最小集 + 可选扩展）

#### 5.1 最小集（对齐我方现状）

- **describe**：返回 schema（字段字典、默认字段集、可过滤字段集）
- **list**：返回实体索引（轻量字段 + 分页）
- **get**：返回实体详情（支持 `fields` 投影）
- **search**：按关键词检索（建议返回索引字段 + 可选 `match_score`）

#### 5.2 可选扩展（建议二期）

> 我方现状不依赖，但交信投可以按需规划。

- **aggregate**：聚合查询（用于趋势/分布等图表），减少前端多次拉取
- **batch_get**：批量 get（减少 N+1 请求）

### 6. 鉴权与审计（推荐）

- **鉴权**：
  - `Authorization: Bearer <token>` 或 `X-API-Key`
  - 服务端依据 token 解析出 `tenant_id/org_id/role`，做 row-level 过滤（如车队维度）
- **审计**：
  - 记录：`who/when/trace_id/action/entity_type/entity_id/fields/filters/latency`
- **最小暴露**：
  - 默认字段集要“去敏”（如手机号/身份证等）
  - `fields` 投影按白名单控制

### 7. 版本与演进（推荐）

- **版本标识**：路径或 Header 二选一
  - Header：`Accept: application/vnd.bus.query.v1+json`
  - 或路径：`/api/v1/query/data`
- **兼容规则**：
  - 增加字段：向后兼容（OK）
  - 更改字段含义/类型：必须 bump major 或新字段替代旧字段
  - action 扩展：向后兼容（OK）

### 8. 与我方现状对齐说明（关键）

我方现状工具层 `query_data` 的最小依赖为：

- `action`: describe/list/get/search
- `entity_type`: driver/vehicle/route
- `limit` 最大 50
- `fields` 点号路径投影

只要交信投实现上述子集，我方即可完成数据源切换；其余（filters/sort/cursor 等）为推荐增强项。

### 9. 建议落地路径（推荐）

- **阶段 A（最小可用，1-2 周）**：实现最小集 + `driver/vehicle/route`
- **阶段 B（2-4 周）**：补齐 cursor 分页、filters、sort、错误码、审计
- **阶段 C（持续演进）**：新增 entity_type（如 alerts/heatmap/report），按 schema 注册扩展
