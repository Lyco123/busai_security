# Agent开发周报 2026-05-27

## 1. 模型服务兼容与 Qwen reasoning 流

**背景**：测试/本地模型网关不一定需要 `OPENAI_API_KEY`，但原链路会在本地提前拦截；Qwen reasoning 模型的流式响应会返回 `reasoning` / `reasoning_content`，需要兼容解析，同时避免 reasoning 配置影响工具调用稳定性。

**本周**：把模型调用、embedding、规则/场景匹配等链路的 `OPENAI_API_KEY` 改为可选；请求头仅在 key 存在时附加 `Authorization`，使无鉴权网关和内网兼容 OpenAI 接口可直接接入。新增 `enable_thinking` / `chat_template_kwargs.enable_thinking` 适配，并在 SSE 解析中捕获 reasoning delta；专家 worker 是否启用 thinking 改由 `OPENAI_EXPERT_THINKING_ENABLED` 控制，默认不强开，减少与 function/tool calling 的兼容风险。

**提交**：`35df8f8`、`e5afe60`、`4f1d170`（2026-05-22～27）

## 2. 流式 probe 与 command/function router 对比

**背景**：上周已看到 command router 在 probe 中有明显耗时收益，但还缺少可复现、可对照的前端比较视图；直接并发比较也会受上游并发波动影响，难判断单次差异。

**本周**：`pipeline-stream-probe` 增加 `routerMode` 参数，支持 command router 与原 function-calling router 显式切换；前端研究页新增 Compare routers 模式，按 command → function 的顺序执行，并记录各自 first byte、first event、first text、elapsed、事件序列和输出内容。补充 Markdown 快照复制，便于把 probe 结果沉淀到文档；布局改成全宽，避免长事件/长输出挤压。

**要点**：
- Compare 模式不再只看单条链路，而是同一 prompt 下顺序跑两条 router 路径。
- probe 事件继续覆盖 opening、router、worker、tool、final 等阶段，便于定位慢点。
- 前端增加会话 ID 搜索过滤，方便按测试 session 回查结果。

**提交**：`a4cac4a`、`ac965dd`、`b4d74a1`、`0a7684f`、`82e761f`、`13f6847`（2026-05-23～27）

## 4. Retrieval：PDF OCR fallback 与独立 OCR 服务

**背景**：扫描 PDF 没有文本层时会直接失败，知识库预览、入库、检索无法端到端验证；OCR 作为重依赖能力，需要独立部署、独立限流和清晰错误码。

**本周**：新增 `agent/retrieval/ocr-service`，提供 FastAPI `/ocr/parse`，支持 PDF/图片解析、文件大小限制、页码范围、超时、错误码和健康检查；OCR 引擎基于 PaddleOCR，采用 worker pool + 子进程隔离，超时或 worker 异常时可替换进程。Retrieval 侧新增 `OCR_ENABLED`、`OCR_BASE_URL`、`OCR_TIMEOUT_MS`、`OCR_LANGUAGE`，PDF 普通解析失败或文本层过短时调用 `parseDocumentWithOcr` fallback，并在 preview warnings 中标记 `PDF_OCR_APPLIED` / `PDF_TEXT_PARSE_FAILED`。Docker compose 增加 `host.docker.internal` 映射，便于容器内 KB 服务联调宿主机 OCR。

**提交**：`98aea3a`（2026-05-26）
