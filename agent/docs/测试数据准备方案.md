## 2. 数据缺口分析

### 2.1 关键问题

**核心问题**：**规则数据完全缺失（0 条）**

这导致以下测试无法进行：
- ❌ Router 测试：所有规则匹配相关的测试用例（R1、R2、R3、R4、R6）
- ❌ RuleReply 测试：所有规则执行相关的测试用例（RR1-RR6）
- ❌ A/B 对比测试：无法对比两种模式在规则匹配场景下的表现
- ✅ Omni 测试：可以部分进行（数据查询、综合分析）
- ✅ RuleConfig 测试：可以测试配置流程，但无法测试冲突检测（需要已有规则）

### 2.2 数据准备优先级

| 优先级 | 数据类型 | 原因 | 影响范围 |
|--------|---------|------|---------|
| **P0（必须）** | 规则数据（≥10 条） | 规则是 Router 和 RuleReply 的核心依赖 | Router、RuleReply、A/B 对比测试 |
| **P1（建议）** | 实体数据补充（各 1-3 个） | 增加测试覆盖度，避免数据单一 | Omni 数据一致性测试 |
| **P1（建议）** | 不存在对象清单 | 测试 Omni 不编造数据 | Omni 数据真实性测试 |

**操作方式**：

**方式一：使用前端规则配置功能（推荐，适合少量规则）**

3. 逐条创建，每条约 5-10 分钟

**方式二：调用 API 批量创建（适合批量创建）**
```bash

curl -X POST https://your-api/rules \
  -H "Content-Type: application/json" \
  -d '{
    "name": "查询驾驶员基础信息",
    "match_text": "用户询问驾驶员的基本信息",
    "data": {
      "reply_goal": "展示驾驶员的基本信息",
      "key_points": ["姓名", "工号", "所属车队", "入职日期", "驾龄"],
      "required_info": [
        {
          "key": "driver_name",
          "ask": "请问要查询哪个驾驶员？",
          "required": true
        }
      ],
      "tone": "professional",
      "examples": [
        "查一下张三的基本信息",
        "张三的详细情况",
        "帮我看看李四的基础信息"
      ]
    }
  }'
```

**方式三：直接插入数据库（不推荐，需要手动生成 embedding）**
```sql
-- 需要手动生成 embedding，不推荐
INSERT INTO rules (id, name, match_text, enabled, priority, version, embedding, data, created_at, updated_at)
VALUES (...);
```

**操作要点**：
- 优先使用**方式一**（前端配置），可以验证 RuleConfig 功能
- 每条规则创建后，验证 embedding 已自动生成
- 记录每条规则的 `rule_id`、`name`、`match_text`、`examples`

## 5. 数据准备工具/脚本

### 5.1 批量创建规则脚本（推荐）

如果需要批量创建规则，可以：

1. **编写脚本调用 `/rules` API**（推荐，会自动生成 embedding）
   ```typescript
   // 示例：批量创建规则
   const rules = [
     {
       name: "查询驾驶员基础信息",
       match_text: "用户询问驾驶员的基本信息",
       data: { ... }
     },
     // ... 更多规则
   ];
   
   for (const rule of rules) {
     await fetch('/rules', {
       method: 'POST',
       body: JSON.stringify(rule)
     });
   }
   ```

2. **使用前端规则配置功能**（适合少量规则，可以验证功能）

3. **直接插入数据库**（不推荐，需要手动生成 embedding）

### 5.2 数据验证脚本

创建规则后，验证数据完整性：

```sql
-- 检查规则数量
SELECT COUNT(*) FROM rules WHERE enabled = 1;

-- 检查规则 embedding 是否生成
SELECT id, name, 
  CASE WHEN embedding IS NULL THEN '缺失' ELSE '已生成' END as embedding_status
FROM rules;

-- 检查实体数据
SELECT kind, COUNT(*) as count 
FROM agent_profiles 
GROUP BY kind;
```

## 6. 实施建议

1. **第一步（P0，必须）**：创建至少 10 条规则

   - 记录名称清单
   - 预计时间：10 分钟

| 任务 | 优先级 | 预计时间 | 累计时间 |
|------|--------|---------|---------|

### 6.3 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 规则创建失败 | 测试无法启动 | 检查 API 权限、网络连接；使用前端配置功能作为备选 |
| embedding 生成失败 | 规则匹配不工作 | 检查 embedding 服务是否正常；重新创建规则 |
| 数据格式错误 | 查询失败 | 参考现有 seed 数据格式；使用 API 创建而非直接 SQL |
| 测试环境数据被清空 | 需要重新准备 | 备份数据准备脚本；记录数据准备步骤 |
