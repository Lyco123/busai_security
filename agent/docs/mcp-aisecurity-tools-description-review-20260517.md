# MCP `aisecurity` 工具 description 审查与改写稿

**审查对象**：`agent/docs/MCP服务设计文档20260424.md` 中的 MCP 接口说明；补充审查 `agent/docs/MCP服务设计文档20260515.md` 相对上一版新增的接口和模型。
**范围说明**：20260424 版文档接口列表写到 22 条，但正文实际可见 19 个接口；接口列表中序号 `16` 重复，且「单位画像指标评分趋势」与「单位画像指标对比」描述存在错位。20260515 版文档接口列表写到 25 条，但正文实际可见 22 个接口；本次增量审查聚焦正文新增的 3 个接口。

**章节顺序**：1～19 与 `MCP服务设计文档20260424.md` 正文 `## 1.`～`## 19.` 一致；20～22 为 `MCP服务设计文档20260515.md` 正文新增接口（与文首「接口列表」表格序号不完全相同处，以正文为准）。

## 字段对齐与相近字段风险（新增）

这类问题会直接影响模型是否把“相近字段”误当成“精确字段”回答。建议写进工具级或字段级 `description`，而不是只依赖专家提示词。

| 对象 | 容易误导的点 | 建议补充到 description 的文案 |
|------|------|----------|
| `driverName` / `employeeName` / `driverId` / `employeeId` / `employeeNumber` | “驾驶员姓名、驾驶员 ID、员工编号、工号”容易被模型混用。 | 明确字段身份：`driverName` 为驾驶员姓名；`driverId` 为驾驶员画像 ID；`employeeId` / `employeeNumber` 为员工/工号字段，不能默认等同。 |
| 驾驶员画像返回的 `routeName` | 用户问“线路 ID”时，模型可能直接把 `routeName` 当成 `routeId`。 | `routeName` 为所属线路名称/线路号，不是 `routeId`。若用户需要线路 ID，应按 `routeName` 继续调用线路画像或线路明细工具查询。 |
| `routeName` / `routeCode` / `routeId` / `intelligenceCode` | “线路名称、线路编码、线路 ID、智能调度线路编码”边界不清。 | 分别说明：`routeName` 是线路名称/线路号；`routeId` 是线路 ID；`routeCode` 是线路编码；`intelligenceCode` 是智能调度线路编码，不能互相替代。 |
| 线路画像工具 `get_mcp_base_absRouteProfileMain_queryRouteProfile` | 工具按 `routeName` 查询，但返回可包含 `routeId`。如果 description 只写“根据名称查询”，模型不容易把它作为补查线路 ID 的下一跳。 | 补充：适用于把其他工具返回的 `routeName` 补查为 `routeId`；若用户问线路 ID 且已有线路名称，应优先调用本工具或线路明细工具确认。 |
| 驾驶员明细列表 `post_mcp_ods_odsJituanBsEmployee_list` 的 `routeName` / `routeId` | 列表返回可能同时有归属线路编号和线路名称，若字段描述不足，模型会混用。 | `routeId` 为归属线路编号/线路 ID；`routeName` 为线路名称。若只命中其中之一，回答时说明字段差异。 |
| 车辆画像返回的 `routeName` | 单车画像中常出现归属线路名称，但不一定返回线路 ID。 | `routeName` 为车辆当前/画像口径下的归属线路名称，不是线路 ID；需要线路 ID 时应继续按线路名称查线路工具。 |
| `organName` / `organId` | 单位名称和单位 ID 容易被等同。 | `organName` 为单位名称；`organId` 为单位 ID。按名称查询得到的结果不能直接冒充 ID，除非返回字段明确给出。 |
| “Body 为空时返回所有” | 实际通常受用户权限、机构范围限制；写“所有”会诱导模型输出全局结论。 | 改为“Body 为空时按当前用户可见范围查询，具体范围以接口权限为准”。 |
| “趋势” vs “对比” | `getKeyRisk`、`quotaScoreTrend` 等描述容易把趋势和指标对比混写。 | 明确“趋势”返回多期评分列表；“对比”返回当前值及同比/环比/同机构等对比值。不要把单日对比结果描述成趋势。 |
| `ppartition` / `dateType` / 分页默认值 | 文档中仍有 `XXXX` 占位，模型会猜默认口径。 | 在真实接口确认前，不写确定默认；写成“可选；未传时由服务端按当前接口默认口径处理，默认口径需以线上接口确认为准”。 |
